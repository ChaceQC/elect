# T3 删除绑定

日期：2026-10-01（Asia/Shanghai）。版本 0.7.0。用户追加的删除能力及枫苑5号-402 的真实删除验收已完成。

## 学校与公开接口

学校当前列表页调用 `roomUserremove([bruId])`：POST /api/base/roomUser/{bruId}，X-HTTP-Method-Override: DELETE，无业务正文。绑定关系 bruId 从本人 B02 取得，不能用 roomId 或本应用 UUID 替代；不在结果未知时切换到直接 DELETE 或其他接口。

公开新增 `DELETE /api/v1/room-bindings/{id}`：本人应用会话、Origin/CSRF、Idempotency-Key，202 为持久受理，查询原 operation。相同键原目标返回原 ID，包括后来重新绑定后重放旧删除键；同键不同目标/同用户未解决目标或默认切换 409，非本人/不可用对象 404。学校写开关仍默认 false。

Bindings 新增 binding_removal_operation_id 与 preference_state，独立恢复撤除槽；Operation 新增 unbind_room 和 binding_status=removed。前端冻结所选目标并要求明确确认，unknown 只读进度，终态更新列表/监控/独立查看；目标 404 清缓存返回列表。

## 台账与屏障

room_0004 保存 removal_was_default 和 preference.removal_operation_id，新增与解绑共用未解决目标唯一键。受理取消旧绑定同步的租约，阻止迟到 B02 在解绑结束后重新提交旧镜像；新同步/绑定/默认受理在撤除槽期间等待。

school_0005 增加 unbind_room 和 absence_first_at，新增/解绑共用同用户目标屏障。Adapter 首次登记前和发送前自行回查 Room 的操作槽、目标、凭据快照和当前 lease_owner；易变租约不进入永久请求摘要，旧 Worker 不能首次发送，新 Worker 可恢复同一上游操作。

若为默认，先 prepare-retarget(target=null) 使旧代次执行/未授权提醒失效；Adapter 再自行读取 Monitoring 的 prepared/null/版本屏障。尚未确认学校解绑前，Room 保留原默认显示，监控 retargeting，关闭动作仍能保存 desired_enabled=false。

外部请求不持 MySQL 锁。SchoolSessions 复用 write_once 的账号锁、token/版本检查和持久 reserve，reserve 提交 dispatched 后只发一次学校请求；从此只回查 B02。明确业务拒绝可终结，未知响应/超时/重启不重发。关系 ID 在首次发送前变化时拒绝，防止删除后来建立的关系。

成功 code 200 不能提前隐藏寝室。两次成功 B02 缺席、MySQL 时间至少间隔 30 秒才能确认；目标重新出现或读取失败重置观察。10 分钟未确认转 unknown，按 5 分钟只回查，保留槽位。合成验收通过回拨观察时间验证数据库判断，真实验收使用正常时间等待。

## 本域提交与恢复

学校确认后，将 binding 标 inactive、余额缓存标 stale、必要时清空默认并增 preference version、审计 Outbox 同事务；保留金额/时间和全部历史表。非默认删除保持原默认与监控；默认删除提交 Room null 偏好证明，再 commit-retarget(null) 清目标/基线，尊重当前关闭意图。

默认清空后 preference.state=blocked，不擅自选择其他寝室；用户明确设置新默认才恢复目标。已提交偏好优先向前完成；明确拒绝在未提交时用新代次补偿原目标，补偿后才公开失败。响应丢失和 Outbox 回滚均从既有台账续作，不再发学校删除。
