# 消费趋势合并监控估算

日期：2026-10-07。版本：0.21.1。

## 展示口径

- 总览近14天趋势与明细的天/周/月趋势统一合并学校C02历史和本人同寝室的成功监控采集。
- 先按上海日期合并：当天学校扣费金额非零时优先使用学校金额（保留负数调整）；学校金额未知时使用监控余额变化估算，学校金额为0但同日监控存在正的余额减少估算时也使用估算。学校0且监控无减少时保留0。之后再聚合周/月，避免在整周或整月上重复累计两种来源。
- 估算取每次成功采集相对`previous_sample_id`所指成功采集的余额减少额；余额相同记0，余额增加或无有效基线不计入。基线须属于同一用户、寝室，且早于本次采集。日期范围不截断基线，首次采集不补0。
- 按用户补充，每个用户、寝室在上海日期内的第一笔有效余额减少归入前一个自然日，其余减少及有效零变化仍归采集当天；按captured_at、id稳定排序，先出现余额不变、充值或无效基线不会占用“首次减少”。这是每天第一次减少，不是当天第一条采集；长期未采集时也只归前一个自然日，不追溯到上一条采集日期、不按天平均分摊。
- 例如10月1日早上首次减少1.20元计入9月30日，当天稍后再减少0.30元计入10月1日。两次采集间的充值、退款、调账和用电无法完全拆分，因此始终称为“余额变化估算”，不能作为学校确认扣费或完整日消费。
- 图表保留现有布局、金额单位与未知断点；提示及展开数据标明估算金额，汇总注明包含估算。学校历史随后同步到非零金额时自动替换对应日期的估算；学校0只有存在同日余额减少证据时才被估算替换，不一律视为缺失。
- 学校用电量与监控电表字段不变，不根据电价或余额反推用电量。全部结果仍保留`complete=false`，昨日完整消费不由估算伪造。

## 实现边界

- Monitoring提供受现有`monitor:browser`权限保护的内部只读按日聚合，按用户、寝室和UTC半开时间范围查询现有样本及持久基线；完整读取所选起始日到结束日的下一天（至多367个采集日期），先判定每日首次减少及归属，再按所选消费日期过滤，返回最多366个日期。结束日的次日首次减少必须补入末日，起始日首次减少归到范围外则排除；不依赖明细页数，不创建分页快照，不调用学校。
- Gateway先通过Room确认本人绑定并读取日历史，再合并Monitoring日估算；总览与明细共用合并逻辑。Monitoring不可用时仍展示学校历史，并显式提示估算暂不可用；原学校同步状态保留。
- `Consumption`新增可选`monitoring_status`，`Bucket`与`ConsumptionSummary`新增可选`estimated_amount`和`estimated_days`。`amount`为按日去重后的学校金额及估算合计，`known_days`为这两种来源有金额的日期数；`estimated_amount`为空表示没有使用估算，0是有效估算。合并版本包含按新归属落入所选范围的成功采集数；旧响应缺字段时按原学校历史展示。学校金额优先级在日期归属调整后应用，再聚合周/月。
- 沿用现有采集时间索引、领域数据库与连接池；无新迁移、Secret、真实学校请求或存量改写。当前运行部署不自动升级。
- 页面可见时趋势每60秒刷新，学校历史任务执行时沿用2秒刷新；手动读取最新采集同时刷新趋势与总览。

## 定向验证

覆盖学校与估算重叠、学校0/负数、充值、余额不变、首次采集、每日首次减少、跨日和范围外基线、日期范围两端、间隔多天、多用户/寝室隔离、跨周/月聚合、Monitoring失败降级，以及总览/明细估算提示。执行结果登记在`PROJECT_PROGRESS.md`，不等同真实学校或部署验收。
