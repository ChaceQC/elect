## 采集快照

- 保留 30 分钟固定成员分页；首页先在本人 monitor 行锁内读取至多 20,001 个样本 ID，超过单快照 20,000 条时返回不可重试的429，提示缩小范围且不附固定等待，绝不静默截断。
- 按本人、绑定、日期范围和有序成员 SHA-256 复用仍有效的快照；新增或迟到提交改变成员摘要，创建新快照，旧分页不变。复用不续期。
- 每用户每分钟至多创建 30 个、保留至多 48 个快照及 60,000 个成员（包括待清理的过期快照），配额检查与写入同事务、同用户锁；分钟额度按实际剩余时间提示，快照数量和成员总量满分别提示回收。正常无变化的首页刷新不消耗创建额度。
- 新 token 由 Monitoring 原有签名 Secret、独立用途前缀、owner 和随机快照 ID 经 HMAC-SHA256 派生，可重新签发同一 token；库内仍只存 token hash，Secret 只在进程内使用。密钥轮换后旧 token 仍可按 hash 翻页至到期；不复用无法由当前密钥重建的旧快照。
- Monitoring recovery 每批最多清理 4 个过期快照、共 1,000 个成员，按快照加锁并跳过其他清理者的锁，先成员后父行；有积压时1秒续批、空闲60秒，按owner公平轮转并受每轮批次与软时间预算约束，详见[快照回收](../runbooks/请求预算与保留归档.md#快照回收)。只记录脱敏清理诊断，不记录 token、用户、样本或密钥。后台关闭时不清理，保留总量配额使故障期间停止扩张。

## 历史同步

- 沿用 Room 本人偏好行锁，先查幂等重放，再检查预算；相同幂等键和摘要重放不扣额度，摘要冲突仍返回 409。
- 每用户新历史 operation 最多 20 个/分钟、120 个/滚动24小时，非终态 operation（含合并别名）最多 32 个；所有新幂等键都计入，避免只合并学校任务但持续增加 operation。
- 每用户最多 4 个未完成 sync、128 个待执行/运行/重试窗口。单次 366 天的 53 个窗口仍可受理；配额耗尽返回 429 和重试提示，待办满时提示等待已有任务完成，拒绝不保留 operation、sync、窗口或 Outbox。
- 同绑定且被现有运行范围完整覆盖的请求合并到原操作。部分重叠仍按独立请求受预算约束，不修改在途窗口、租约或原请求范围；成功缓存继续展示，但不当作永久新鲜，用户显式同步仍可刷新。
- 沿用 operation 至少 180 天的幂等保留契约，不另建无界映射表；合并别名同样受速率及待办上限约束。
- 0.19.3修复多窗口合并传播：别名按直接上游及同owner/type/绑定持续跟随，不能因阶段从merged变为read_school而停止更新；全部窗口结束才进入终态并释放待办预算。存量仅通过独立的默认dry-run入口审查，见[维护手册](../runbooks/历史合并修复与登录执行门.md)。
