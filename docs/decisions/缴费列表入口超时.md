# 缴费列表入口超时

日期：2026-10-08；版本：0.22.7；范围：本轮只读审查问题6。

## 问题与决定

学校缴费列表一次性返回D04分页结果，Adapter整体执行预算为45秒，前端等待55秒。HTTPS和私网HTTP入口此前沿用普通API的35秒读取超时；当查询耗时35至45秒时，Nginx会先返回504，后端完成的正常结果或超时后保留的部分结果无法到达浏览器。

在两份Nginx模板现有 `/api/` 内增加缴费列表的嵌套正则location，显式使用原 `proxy_pass $gateway` 并覆盖 `proxy_read_timeout 50s`。匹配路径为 `/api/v1/room-bindings/{id}/payment-records`，id限定单个非空路径段并由原Gateway继续校验UUID；查询参数不参与location匹配，起止日期不影响路由选择。路径末尾锚定，其他寝室接口、支付订单与近似路径不扩大预算。

预算按Adapter45秒、入口50秒、浏览器55秒衔接。Nginx读取超时是相邻上游读取之间的空闲超时，该接口一次性返回，因此覆盖学校查询阶段，并为内部转发和响应返回留出余量；不替代Adapter原有整体deadline。内部ServiceClient原100秒传输超时无更短限制，本轮不扩大后端执行预算。

嵌套正则location必须显式声明 `proxy_pass $gateway` 以建立代理处理器，沿用原上游及完整路径/查询参数。它继承原API的Host（HTTPS为`$host`，私网HTTP为`$http_host`）、转发协议/来源/请求ID、3秒连接超时、禁止上游重试及`Cache-Control: no-store`，保留内部TLS校验。普通API35秒、登录70秒和登录限流、私网Host限制、静态资源缓存保持。

## 交付与生效

- 只修改两份入口模板及受影响的版本元数据、文档；问题1—5修复保留。
- 不修改API字段、数据库、Secret、学校调用额度或副作用开关。完整结果、部分结果、首屏失败与429原有语义保持。
- 现有部署未升级；后续部署须使用新模板，通过Nginx预检并重新渲染、重建入口后生效。已启动容器不会因仓库模板修改自动加载新预算。
- 回退旧模板会重新引入35秒截断；本次无数据迁移或存量改写。
