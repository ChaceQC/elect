# 登录拒绝与恢复健康隔离

日期：2026-10-08（Asia/Shanghai）；输入：dev / b51a897；版本：0.22.2。范围仅为本轮全仓审查的问题1，问题2—6不在本次修复内。

## 原因与处理边界

Identity先保存authenticating，再调用Adapter认证。Adapter账号/浏览器限流在验证码消费之前执行，429不会产生已验证暂存。原前台跳过429终结，恢复又保留暂存404，导致无有效验证码或密码的请求留下持久健康失败，60秒后触发整个core协调退出。

恢复器没有密码，不能重新发起学校认证。应终结无法从暂存恢复的登录尝试，并保留真实依赖故障的监督能力。

| 位置与状态 | 处理 |
| --- | --- |
| 前台认证返回明确4xx（含429），持久状态仍为created/authenticating/staged | 条件更新为failed，保留错误码；原API状态、错误码与Retry-After继续返回，不签发会话 |
| 恢复查询暂存404，仍为authenticating/staged | 条件更新为failed；兼容原版本已持久化NOT_FOUND的记录，后续退出恢复集合 |
| 恢复状态查询429或5xx | 保留待恢复状态、错误与5秒退避；仍计入60秒连续失败预算 |
| identity_committed/activating收到404、429或5xx | 保留已提交身份、凭据协调和依赖失败；不得按未认证尝试终结 |
| 本地LoginBusy | 保持原执行门/命名锁繁忙语义；不产生新健康失败，也不能清掉已有依赖失败 |

前台失败处理与后台恢复共用`reject_uncommitted`，SQL只更新仍在提交身份前的状态；恢复器释放锁后，即使前台已经推进，也不能由迟到拒绝覆盖identity_committed、activating或终态。公共ProcessControl、Heartbeat及健康失败阈值保持原实现。

暂存迟到不会自动激活：已终结attempt无法推进身份或签发会话，Adapter暂存按原保留/清理规则处理。已经验证并激活的凭据不受失败尝试影响。收到限流的用户仍按原Retry-After等待，重新取图后使用新的登录尝试；旧尝试的重放按既有规则返回CAPTCHA_EXPIRED。
