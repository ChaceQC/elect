# CI 并行验证与触发分层

日期：2026-10-06（Asia/Shanghai）。本轮增加纯Markdown分支push跳过规则，不改变应用版本、业务行为或生产启动顺序。

## 范围与门禁

第一轮保留全部触发的完整验证并完成并行验收。第二轮按事件分层；2026-10-06按用户最终要求，再对分支push增加`paths-ignore: ['**/*.md']`。仅所有变更路径均为Markdown时不触发整个workflow；不整目录忽略docs，OpenAPI、内部契约、状态YAML和schema JSON仍触发检查。已触发的运行不按文件缩减测试，不复用跨运行测试结果。

| 触发场景 | 执行内容 | check要求 |
| --- | --- | --- |
| 非main分支push，仅Markdown文档 | 整个workflow不触发，不构建镜像 | 无check；记录按路径规则未触发，不能声称success |
| 非main分支push，含任意非Markdown文件 | 前后端快速检查与构建 | 两组success、三组完整验证skipped |
| main分支push（PR合并后） | 不触发CI | 使用合并前PR完整门禁，不重复验证 |
| 目标为main的PR | 快速检查及三组完整容器验证 | 五组全部success |
| vX.Y.Z标签push | 快速检查、完整验证、发布受测runtime | 五组全部success后才能发布 |
| 手动运行（默认full） | 完整验证；分支可选择quick | 根据所选范围严格汇总 |

手动在标签上运行始终完整验证，即使选择quick也不能降低标签验证范围；手动运行不发布。非版本标签不自动触发。不传手动选项时默认full。PR与包含非Markdown文件的非main分支push可同时运行，只有PR执行重型容器演练；纯Markdown push跳过，文档PR仍完整，避免必需check因路径过滤长期pending。GitHub标签push不计算路径过滤，vX.Y.Z标签保留完整验证及发布门禁。main的push整体排除，合并后不产生第二次CI；主分支禁止直接推送，严格PR完整检查与最新目标祖先要求保持。

跳过范围限于`.md`，不包括文档目录中的JSON、YAML、图片或脚本。混合提交即使只有一个非Markdown文件也不跳过；多提交push由GitHub对该次push的变更路径判定。纯文档收口可记录上一个业务/配置提交的成功证据，但先前失败不能被文档提交的无运行状态覆盖。

前后端检查与构建分别运行；完整场景两端成功后，业务与消息集成、13／30 容器兼容、七容器与交付恢复在三个独立运行器并行。`容器验证 / check`以always()执行，并根据事件/ref/手动范围独立判定必需结果，不从上游是否跳过推断范围。缺失、失败、取消、未知结果和完整场景的跳过均拒绝；快速场景仅三组完整验证必须为skipped，防止条件漂移悄悄增加重型任务。标签发布单独依赖check，且限定版本标签push，只有发布作业拥有contents/packages写权限。分支与PR分别取消过时运行，标签单独分组且不取消正在发布的同标签运行。

## 覆盖与状态契约

| 作业 | 现有覆盖 | 前置与结束状态 |
| --- | --- | --- |
| 后端 | Ruff、单元、契约、schema、迁移清单及 SQL、查询受理数据库定向验证 | 构建本次 runtime/test；独立临时 MySQL 与 internal 网络 |
| 前端 | 契约、lint、类型、单元、构建、浏览器 | 构建本次 runtime/browser-test |
| 业务与消息集成 | test-stack 全部业务、test-resource-parameters、test-execution-efficiency、100 计划容量、test-t7-browser | 独立空库 combined；合成驱动前停止所有应用；生产浏览器使用恢复覆盖禁用后台 |
| 13／30 容器兼容 | test-low-resource 的七域、MQ 降级、恢复禁用和原卷 13→30→13 | 独立空库 combined；结束恢复 combined 健康 |
| 七容器与交付恢复 | test-image-delivery、test-core 的 13→7→13/50 监控、test-t7-recovery | 独立空库 combined；恢复使用独立目标项目，目标卷必须为空；结束只保留基础服务供检查 |

环境准备从 test-stack 抽出，负责校验镜像、一次性 Secret、空库迁移、基础健康及按组启动；不会执行业务用例。普通本地 test-stack 保留一条命令构建、准备并完整验证的入口，CI 使用已加载镜像并禁止重建。每个独立脚本显式检查其前置状态，不依赖其他作业留下数据库内容。

CI 使用含 run ID、attempt 和组名的独立项目名、目录、卷与网络。Secret 在各运行器内生成，不上传；恢复所需 Secret 仅在交付组内部复制到独立恢复目标。清理仅删除本次明确命名项目的容器和卷，不操作其他项目。生产 start/upgrade 仍串行启动；无源码部署和模式切换演练继续调用真实入口。

## 镜像传递与缓存

前后端在实际触发workflow的场景都构建runtime和测试镜像并执行现有快速检查，包含后端查询配额数据库定向验证、前端浏览器与构建。仅完整场景输出镜像包，以及版本、检出提交、镜像ID、文件SHA-256；快速场景跳过打包和上传计时/传输，避免无人消费的镜像成本。PR使用默认检出的合并结果；构建、测试和清单校验都针对该提交。消费方先核对版本、提交和包校验值，再加载并核对镜像ID/OCI标签。恢复复用本次runtime/test，不再构建ops。

BuildKit GHA 缓存按前后端/目标分开，只缓存构建层；每次重新执行检查和业务验证。标签发布重新校验并只加载受测 runtime，再由现有 publish.sh 发布，不重新构建。Actions artifact 只包含镜像和公开校验信息，不传卷、会话、测试凭据或完整临时目录。

打包、上传、下载、加载分别记录耗时。镜像大小和传输开销以实际 Actions 为准；后续比较冷缓存与命中缓存，不能用理论并行度代替提速证据。
