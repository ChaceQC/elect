# 登录与页面重载自动查询

日期：2026-10-07。版本：0.21.2。

## 触发与范围

- 成功登录、重新认证或浏览器重载恢复本地会话后，在总览或电费明细首次展示对应寝室时，自动调用既有余额刷新和历史同步接口，不再只读取旧缓存。先展示最近成功数据，异步任务完成后重新读取余额、消费趋势及总览。
- 自动查询等待学校资料可用、凭据为active且允许使用凭据；资料失败或需要重新认证时，保留本地登录和缓存读取，不自动提交学校查询。资料恢复后执行尚未尝试的查询。没有可查看寝室时不创建请求。
- 总览同步接口返回的近14天范围；明细同步当前已应用的日期范围，默认上海日期最近30天。保留URL中的寝室和日期，不更改默认寝室或监控目标。
- 每轮已认证页面中，每个寝室的余额刷新、历史同步各自动尝试一次。React StrictMode、缓存失效、资料刷新、天/周/月切换及总览与明细间导航不重复发起。同轮改日期后仍可手动同步所选范围，浏览器重载会以当时范围开始新一轮。

## 受理、恢复与反馈

- 复用QueryAction、OperationController和既有operation轮询。优先恢复该路径的原请求；已有operation_id或服务端历史同步摘要时只跟踪原操作，受理未知时沿用原幂等键及原日期重试，不创建替代请求。
- 429沿用Retry-After及sessionStorage中的原键/退避时间；自动尝试失败后不循环重试，按钮保留原请求恢复入口。登录、退出与切换账号仍使用既有API epoch、缓存清理和用户恢复记录隔离。
- 自动刷新使用原按钮的旋转图标和无障碍状态；错误、未知、取消及120秒后的暂停恢复提示保留。202只表示受理，只有服务端终态触发结果重新读取；失败不清空最近成功余额或历史。
- 此变更只增加前端触发，不修改API字段、学校协议、消费合并口径、采集/邮件/支付开关、后台调度或请求预算。无数据库迁移、Secret或存量改写；现有运行部署不随源码升级。

## 定向验证

组件覆盖登录、会话恢复、StrictMode去重、页面切换、资料不可用/恢复、已受理恢复及429原键/原日期保留；浏览器覆盖桌面/手机的余额与趋势自动更新、重载、日期范围、手动入口与刷新反馈。执行结果记录在PROJECT_PROGRESS.md，不等同真实学校联调或部署验收。
