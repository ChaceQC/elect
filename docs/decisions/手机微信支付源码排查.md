## 找到的H5请求

### 1. 接口声明和实际URL

[主包](https://sdgl.hbue.edu.cn/mobile/static/js/index.11d65048.js)声明的 `wxpay` 核心调用为：

```javascript
{ url: "/api/wx/pay", method: "get", params: t }
```

同一主包模块 `b21c` 配置 `baseUrl: "https://sdgl.hbue.edu.cn/api"`。公共请求模块 `5a76` 使用：

```javascript
url: t.baseUrl || g + t.url
```

其中 `g` 来自该baseUrl，`wxpay` 没有单独覆盖baseUrl。因此学校这份源码的最终路径确实是：

```text
GET https://sdgl.hbue.edu.cn/api/api/wx/pay
```

参数：`userId`、`buildId`、`orderType=0`、`payMethod=1`、`orderAmount`、`tradeType`。请求封装从当前学校会话取得Bearer token；默认超时15秒。本轮曾使用30秒读取预算，仍为ReadTimeout；单 `/api/wx/pay` 路径实测404。

### 2. 唯一业务调用处

[中文充值详情页](https://sdgl.hbue.edu.cn/mobile/static/js/pages-topUpPayment-CN-details.0ae21658.js)的 `wxZF()` 检查 `navigator.userAgent`：

- 同时包含 `MicroMessenger`、`wxwork`：企业微信，传 `tradeType="MWEB"`。
- 其他环境：传 `tradeType="NATIVE"`。
- 只有 `code=200` 且企业微信时，读取 `data.mwebUrl` 并跳转。
- 回跳地址硬编码为 `https://sdgl.hzau.edu.cn/mobile` 加当前路由，域名与本校不一致。

这是客户端JavaScript选择请求参数的逻辑。给HTTP请求加普通安卓User-Agent，不等于这段函数就会执行，也不等于服务端必然改变支付产品。

用户进一步要求实际尝试该分支后，已用项目身份重新认证并唯一匹配原指定寝室，以1.00元、`tradeType=MWEB`、同时包含`MicroMessenger/8.0.54`和`wxwork/4.1.30`的安卓UA，以及学校Origin/Referer，对上述完整URL发送一次请求。源代码的企业微信UA条件成立，但30秒后仍为ReadTimeout，未取得HTTP状态、业务响应或mwebUrl。前后D04待支付列表均为空，不据此断言未建单；此次显式试验及此前未知尝试分别保留，不自动重试，也未付款。该试验使用项目CAS/SDGL身份，不代表已完成企业微信OAuth认证。

### 3. 实际确认按钮没有绑定H5方法

该分包中 `wxZF` 仅出现一次，即方法定义。模板“确认支付”的点击绑定为 `t.quzhifu.apply(...)`，没有调用 `wxZF()`。

`quzhifu()` 对电费调用 `phonePay`，该接口在主包声明为：

```javascript
{ url: "/base/order/phonePay", method: "post", data: t }
```

实际路径为 `POST https://sdgl.hbue.edu.cn/api/base/order/phonePay`，传本人/寝室/金额和电费微信字段，收到 `data` 后直接打开学校支付页。该方法没有根据UA选择MWEB。英文充值详情页同样走phonePay。

`pages-topUpPayment-CN-payment.a64aa283.js` 中的另一个“支付”展示页，其 `quzhifu()` 只是前端导航到 `RechargedSuccessfully`；没有实际支付接口调用，不能把这个页面当成JSAPI实现或真实成功证据。

## JSAPI排查结果

57份JS中没有发现 `JSAPI`、`WeixinJSBridge`、`getBrandWCPayRequest`、`chooseWXPay`、`paySign`、`prepay_id`、`unifiedorder`、`h5_url` 的业务实现。

vendor包只出现一次 `requestPayment`，位于uni-app平台API名称列表，没有调用参数、签名生成或学校下单请求。`openId/openid` 相关命中来自忘记密码表单、通用云开发认证SDK，不属于支付调用。泛化的 `H5` 命中主要是内嵌图片数据，不能据此认定存在H5支付。

结论限定为本次公开构建版本：找到一条未被确认按钮调用的MWEB分支，没有找到可用JSAPI业务请求。学校后端是否另有接口，无法通过这些前端包确认。

## 全流程手机头对照

用户要求支付请求带手机头后，先复核此前D01/phonePay已使用安卓UA，发现后续独立E03取码没有沿用。随后明确复用403对应的原1元订单，E01、E02、E03、E04均设置同一安卓Chrome UA、`Sec-CH-UA-Mobile: ?1`、`Sec-CH-UA-Platform: "Android"`、中文Accept-Language，按页面/图片选择Accept；POST继续使用当前隐藏字段、Cookie、Origin、Referer及UTF-8表单编码。不加入已验证会破坏学校普通表单的AJAX参数。

- E01–E04全部HTTP 200，并从实际发出的request对象逐步核对手机UA和移动标识；没有再次请求D01。
- E02/E03各进行一次本轮显式试验，发送前持久记录，未知不自动重放；同一学校电费订单不等于学校支付流水一定不变。
- 得到新的原生 `weixin://wxpay/` 付款码，没有H5/JSAPI参数；已用新码更新临时页并核对href编码。
- 用户安卓真机重试后仍报告出现打开确认但未打开。此前同页不带订单的 `weixin://` 已由用户确认可打开微信。
- 未付款、未改正式页面或部署；凭据与票据不进入公开记录，私有结果沿用本机DPAPI密文保存。
