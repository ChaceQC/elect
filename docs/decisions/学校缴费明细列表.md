# 学校缴费明细列表

日期：2026-10-07；版本：0.22.0。

## 页面和金额口径

- 电费明细页在监控采集下方新增缴费明细列表，沿用浅蓝卡片、表格和分页。共用寝室、开始/结束日期，草稿应用后生效；切换寝室/范围回第一页，采集翻页及天/周/月不触发缴费重新查询。
- 展示学校已支付电费记录的缴费时间、实缴金额、支付方式和学校订单号。缺少缴费时间显示未知并附创建时间，不把创建时间当作付款时间；未知渠道保留代码。
- 总缴费按整个学校查询结果的payAmount用Decimal求和，前端每页10条的翻页不改变总额。完整空结果为0；不完整时total_amount=null，仅展示已读取合计。
- 数据来自学校D04，不依赖本系统订单，因此可展示在本系统之外产生、且学校向该账号开放的缴费记录。不以余额增加量反推缴费。

## 接口与资源边界

新增 `GET /api/v1/room-bindings/{id}/payment-records?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`。复用上海日期校验（含首尾、最多366天、不晚于今天），与监控采集使用同一组值。

Gateway每次重新验证会话，Payment的 `/browser/records` 使用既有payment:browser，转发Adapter的 `/payments/records`（既有school:payment）。Adapter先通过Room的query-target验证本人active绑定，再使用学校会话读取D04；浏览器不能指定学校寝室标识。无新增权限、Secret或迁移，不调用建单、付款或订单确认逻辑。

D04固定orderType=0、payStatus=2，**不传payMethod，不限定微信渠道**。日期按学校列表协议原样传入。本次真实账号确认不传渠道返回1/2/3三类渠道、17笔，只筛微信返回15笔。complete只表示本次学校分页读全，不代表学校包含所有线下或未开放渠道。原支付终态确认逻辑不修改。

响应PaymentRecords含items、学校total、total_amount、known_amount、complete。条目仅含id/created_at/paid_at/amount/method，不返回学校用户标识、票据或原响应。验证寝室、已支付/电费状态、精确金额、时间、分页数量和重复订单。

每次最多50页（每页10条），整体45秒，沿用账号锁、学校并发与认证检查。分页总数变化、重复、超时或结构失败后保留已读部分并标记不完整；首屏失败返回标准错误。认证/授权和429不降级为成功，前端遵循Retry-After（429缺少提示时60秒），不自动重试。

0.22.7将HTTPS和私网HTTP入口的本接口读取超时单独设为50秒，浏览器仍等待55秒，避免35秒普通API预算截断正常或部分结果；其他API预算与读取口径保持，部署生效方式见[入口超时修复](缴费列表入口超时.md)。

前端在学校资料active且授权可用时进入查询，缓存按账号/寝室/范围隔离，60秒新鲜度；窗口聚焦、网络恢复、采集和趋势刷新不重发。手动刷新重新读取整个结果，失败保留此前数据和恢复入口；会话层负责跨账号清空缓存。大范围未读完时提示缩小范围或重读。
