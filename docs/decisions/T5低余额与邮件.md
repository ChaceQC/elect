# T5 低余额与邮件实施决策

日期：2026-10-01；状态：实施中，真实 SMTP 投递待验。

用户已将本轮范围明确调整为包含真实投递。SMTP 配置和唯一指定收件人由本地 email_auth.txt 的五行内容提供，只允许专用测试进程在内存解析，不直接查看或输出。先验证模拟 SMTP 故障边界，再在独立验收环境临时开启真实发送；不向其他用户试发，默认开关仍为 false，实际结果单独记录。

## 事件与次数

- 采集成功的栅栏事务内判断 Decimal 余额，严格小于阈值触发；达到阈值停止未授权提醒，达到阈值加 1.00 元关闭事件。失败、旧代次、过期或未来样本不参与。
- 每条成功样本最多预留一个 slot；发送和未知结果占用序号。取消的未授权 slot 可由下一条新鲜样本重新预留同一序号，使用新 slot ID，保留旧台账。数据库以事件/有效序号唯一约束防重复；同一样本的重入检查在 monitor 锁下执行。
- 仅改间隔/次数迁移事件与计数，旧代次未授权 slot 取消。已授权、已发送和未知序号不重用；已用名额超过降低后的上限时停止新增。
- 冷却跨事件保留，以当前 interval 和最近许可/接受时间判断。明确失败不增加已发送次数；永久拒绝或重试耗尽结束该 job，并保持 email_failed，当前 episode 不反复创建同一失败提醒。

## 投递与恢复

- MQ 事件只携带引用，不携带收件地址或正文；Notification 通过受限内部接口读取本人 slot 快照，用本域独立密钥加密邮箱。
- job 按 slot 幂等，Message-ID 固定；租约与 execution_epoch 防多 Worker 重复执行。每次投递重新申请 Monitoring 许可；失联禁止发送。
- 在发送 SMTP DATA 正文前持久记录发送边界；只有明确未接收的错误可重试。DATA 后断连、接受后落库失败或正文边界后的进程崩溃进入 delivery_unknown，不重发。
- 初次尝试后最多重试三次，分别延迟 1/5/15 分钟，每次仍受新鲜度、代次、冷却与取消检查约束。固定 Message-ID 不能视为 SMTP 幂等保证。
- Notification 的进度/终态以本域 Outbox 回报，Monitoring 使用 Inbox、job 版本与 epoch 幂等处理。未到正文边界的恢复可安全释放旧许可；正文边界后的恢复占一个名额。
- 连续超过三个失败采集周期产生独立故障事件，成功采集关闭；不占用低余额额度，也不另行发送未约定的故障邮件。

## 变更范围与验证

Monitoring 新增事件规则、样本提交钩子、独立故障事件及 slot 状态镜像；Notification 新增 Worker、恢复器、SMTP 传输与模板；新增本域迁移、Secret/队列权限、Compose 进程和前端状态。发送许可代码将按授权检查/结果镜像职责拆分，以避免在同一文件混入 SMTP 或跨库访问。

验证包含真实 MySQL 的事件次数/回差/配置变化、并发领取/取消、签名消息重复与丢失、模拟 SMTP 接受/临时和永久拒绝/DATA 后断连、进程崩溃恢复，以及前端桌面/手机状态。模拟器接受不等于真实邮箱收件。
