# 订单自动回查时限

日期：2026-10-08（Asia/Shanghai）；版本：0.22.9。

## 问题与规则

未付款订单原先没有自动处理总时限：正常回查每轮结束后2秒再次安排，查询错误退避30秒，建单/二维码未知任务也会持续恢复。关闭页面不影响后台，学校过期/关闭结果尚无可用的确认映射，因此放弃付款的订单可能长期占用学校查询资源。

本系统受理订单后自动处理最多15分钟。期限持久保存在Payment订单，覆盖支付回查与原订单建单/二维码任务的后续领取，正常2秒与错误30秒间隔保持；重启、读取订单、重放建单或重新获取二维码都不能延长期限。到期不再领取新的学校调用，已经领取的任务按原170秒执行预算结束；在途结果仍可确认付款。付款确认后的余额刷新保持既有终态和临时故障恢复规则，不受未付款窗口截断。

暂停只停止本系统自动处理，不修改学校订单状态，不认定付款失败、学校过期或取消，不释放未解决订单占位，不删除原任务、幂等键、发送台账或票据。主动“停止处理此订单”仍沿用原取消流程。

## 原订单恢复与页面

Order新增可选`check_deadline_at`和`check_paused`，旧响应缺字段时前端保持兼容。`check_paused`由服务端根据期限和在途租约判断；在途尚未结束时页面继续读取状态，结束后暂停前端订单/二维码轮询并显示原结果和恢复入口。

`POST /payment-orders/{id}/resume-check`使用本人Cookie、Origin、CSRF和`expected_version`，只恢复原订单及其未完成任务，开启新的15分钟窗口，不生成新订单或新学校发送标识。活动窗口内重复请求返回当前订单且不续时；缺版本428、过期版本409、跨用户404、终态或已主动停止409。尚有在途任务时不并发恢复，响应不确定时先读取原订单对账。

恢复按钮仅在服务端确认暂停后显示，文案为“继续核对原订单”；暂停时隐藏旧二维码，保留“停止处理此订单”。订单GET保持只读，不因关闭/打开弹窗或重载页面自动恢复。

## 迁移与部署

新增`payment_0007`，仅添加可空的UTC `check_deadline_at`字段。新订单受理时写入期限；旧订单无值时按原`created_at + 15分钟`解释，超过期限的存量任务下次领取即暂停，不给旧订单重新开启窗口，也不批量改写历史终态。

升级先停止所有旧Payment后台领取角色，执行Payment迁移，再配套升级Gateway、Payment和前端。其他领域迁移、Secret、业务开关和容器数量不变。旧镜像不识别期限，直接回退可能恢复无限回查，应保持Payment后台停止直至部署兼容版本。本轮交付源码与验证，不自动升级现有部署。

## 验证

定向覆盖新/旧订单期限、超时零外部调用、失败退避、后台重启、二维码迟到写入、在途确认付款、付款后余额刷新、原任务恢复/重复恢复、版本/归属/取消保护及桌面/手机暂停和恢复。实际执行结果记录于`PROJECT_PROGRESS.md`，合成结果不代表真实学校付款验收。
