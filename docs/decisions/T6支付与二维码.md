# T6 支付与二维码

日期：2026-10-02。工程版本0.10.0。状态：T6-01..03实现与合成验证完成，指定真实验收进行中，T6-04/P7-06与T6整体未完成。

- 初始金额规则为应用保护政策：CNY、1.00–500.00、步长1.00；capabilities 返回 amount_policy_source=application_policy，不称为已验证学校上限。余额与充值金额没有大小约束。
- 本地订单、create_order 操作、唤醒 Outbox 和审计同一 Payment 事务提交。本人幂等键重放返回原 order_id，改内容409；同用户/寝室未解决订单阻断换键，409 existing_operation_id 指向本人原订单。
- 学校票据、学校订单标识、prePayId 和支付 Cookie/隐藏字段由 Adapter 独占加密保存；Payment 仅使用本地 order_id/upstream_operation_id，不接收明文 URL。各域不跨库读取。
- 能力同时要求有效绑定、有效后台学校授权、两项支付写开关与真实验收标志；默认关闭。原键重放与原订单读取不因关闭开关而丢失。
- 用户指定真实验收使用 auth.txt 本人账号、默认寝室，以及一个高于最新余额、一个低于最新余额的金额。采用满足关系的整数；超过应用范围时不得绕过政策。同寝室先前未解决订单必须先核对，不能为跑第二笔而释放槽位。实际扫码付款由用户操作，建单/二维码/支付确认/余额查询分别记录。

## 持久阶段与恢复

school_0006增加adapter_payment_orders，关联原upstream_operations；URL、prePayId、可空SDGL标识、查询观察全部使用Adapter信封/AAD密文。payment_sessions持久存Cookie、每页最新隐藏字段、E01..E04阶段、租约和已验证图片。E02/E03使用由本地order_id/阶段确定的永久台账ID；发送标记先提交，响应/新阶段同事务提交。响应丢失、5xx、HTML无法解析或发送后崩溃均为unknown，不回退E01并重发。E04失败只重取现有图片URL。

payment_0002/0003增加本用户事务锁、同订单一个开放操作、QR合并请求的每个原键引用、回查租约和余额刷新引用。Worker每10秒续租；恢复器只接管过期任务，迟到epoch不能覆盖新结果。Outbox签名唤醒经Inbox验证；MQ失败继续MySQL扫描。二维码GET不推进外部表单，qr-refresh受理后由Worker继续已有阶段。

支付HTTP客户端与CAS/SDGL客户端独立，逐跳检查已知主机/路径、固定公网IP、2MiB上限，不跟随会重放POST的307/308，不发送Authorization或AJAX参数。现有学校E链路仍为文档已确认的cwcwx HTTP，仅该主机允许HTTP；不将它描述为HTTPS。图片按真实字节解码、限制2048×2048，PNG/JPEG原样输出，其他可解码格式归一为PNG；不按学校text/html头误拒绝有效PNG。本应用图片只有本人Cookie鉴权、no-store、nosniff，无上游URL。

## 支付确认与范围

D02已验收映射初始为空：SUCCESS/2/PAID等参考候选值都保持status_unknown；D04没有精确明细映射，空列表保留submit_unknown。合成测试临时注入精确映射验证终态/余额任务，不能作为真实状态证据。只有Adapter确认终态后Payment释放未解决槽，付款后持久请求Room余额刷新，不计算旧余额+金额。余额刷新成功只表示学校查询成功，不单独保证充值到账。

指定真实只读已验证本人默认寝室与最新B02，关系所需整数为10元/11元。已执行一次10元D01/E链路并取得QR，用户决定本轮暂不扫码；原订单实际终结后才按最新余额重新选择较大金额。公共验收标志保持false；专用进程内仅对指定目标直接受理正常持久订单，短时允许其D01/表单，结束恢复false。不执行自动扣款，不发布二维码票据到仓库。未完成真实状态/到账之前不勾选T6-04、P7-06或M3。

下一步：代码交付后，待用户继续付款验收，再只读回查原10元订单的D02/D04与学校余额，取得真实状态样本；首笔未解决期间不执行第二笔。
