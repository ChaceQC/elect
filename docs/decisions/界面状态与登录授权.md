# 界面状态与登录授权

日期：2026-10-04；开发版本0.18.1。本次按用户提供的13项分析修复，维持浅蓝参考布局。

2026-10-05更新（0.18.3）：支付和解绑进度改为可见时每2秒持续刷新，隐藏暂停、终态停止；下文120秒暂停只继续适用于其他操作/采集。后台独立调度与确认边界见[支付与解绑自动更新](支付与解绑自动更新.md)。

## 登录与授权

协议更新为2026-10-04.1，内容摘要随正文重新计算。用户阅读并同意协议后，登录/重新认证即授权后台使用加密凭据恢复学校登录，范围包括本人查询、明确确认的绑定/解绑和缴费、已开启的监控与提醒。授权不自动开启监控或外部写入。按用户追加要求，登录页移除额外授权长说明及阅读提示，只保留协议入口和同意勾选；完整条款在协议正文中阅读。

LoginRequest保留credential_use_allowed字段并收紧为true，避免新协议下再次提交false。旧版协议仍按现有逻辑拒绝并要求重新阅读。既有consent和凭据不批量变更；历史未授权账户需重新认证。账户移除撤回按钮，但保留旧持久操作的只读进度与后端撤回Saga，旧操作完成后可重新认证。

## 13项问题对应规则

| 分析项 | 修复后的行为 |
| --- | --- |
| 1 错误的409提示 | VERSION_CONFLICT才提示设置冲突；SCHOOL_REAUTH_REQUIRED引导账户重认证，OPERATION_IN_PROGRESS提示等待。网络未知保留草稿并核对结果。 |
| 2 重认证丢失授权 | 登录/重认证均在阅读同意新版协议后传true，无独立后台授权复选框。 |
| 3 保存覆盖新输入 | 提交期间锁定所有编辑项和冲突处理按钮，取消较旧的设置读取；编辑处理器也拒绝保存中的修改。 |
| 4 余额不自动过期 | 总览/明细/绑定列表根据fetched_at和服务器校准时间计算，超过300秒标记过期；服务器stale始终保留。页面重新可见立即更新时间。 |
| 5 支付取消误导 | 主按钮“停止处理此订单”、确认“确认停止处理”、本地终态“本系统已停止处理”；明确学校订单/二维码可能仍有效，不退款。 |
| 6 开关生效不一致 | 仅保留监控开关和保存按钮，旁边显示真实状态与保存说明。关闭优先仅提交enabled=false，其他草稿保留并另行保存，无效邮箱/间隔不阻碍停止。 |
| 7 邮件限制隐藏 | 邮箱区域直接说明未启用邮件时仍可配置/采集，但不会发送提醒。 |
| 8 默认切换影响不明 | 列表说明监控跟随默认，切换前确认目标和后续采集/提醒影响；确认使用点击时的版本。 |
| 9 授权范围不足 | 协议正文覆盖查询、绑定/解绑、缴费及监控；登录页不重复堆放说明，旧未授权账户绑定入口直接引导重新认证。 |
| 10 功能关闭反馈过晚 | Room列表附带binding_write_enabled，列表/首次引导/直达选房均检查；缴费入口预取能力，禁用时说明原因，原订单仍可恢复；关闭能力时不展示新建金额表单。 |
| 11 轮询静默暂停 | 支付和解绑每2秒持续更新；其他operation/run使用120秒窗口及恢复入口。隐藏页暂停，终态不继续轮询，已支付但余额待刷新继续查询。 |
| 12 技术文案 | 绑定恢复改为“查看上次提交结果”，设置冲突改为“按最新设置继续保存草稿”，凭据旧操作显示正在停止后台任务。 |
| 13 空白分页 | 绑定总数变化后将页码限制到有效范围；校正前仍保留上一页入口。 |

## 接口与交付边界

2026-10-04追加交互调整：移除寝室操作、余额/历史同步、旧凭据操作及支付订单中的“查询最新进度”“查询认证进度”“查询支付结果”按钮，进度沿用自动轮询与终态刷新。0.18.3支付和解绑持续更新，其余操作在120秒自动轮询暂停时保留“恢复自动更新”；刷新学校余额、同步历史、重新获取同订单二维码和未取得受理编号的原请求恢复仍保留。支付提示同步改为等待自动更新，不再引导点击已移除的按钮。

只有LoginRequest约束和Bindings展示字段变化，无表结构迁移。binding_write_enabled由实际school_binding_writes开关决定，不为页面启用外部能力。前后端与协议应同步升级。学校/SMTP/支付真实验收、原业务恢复、第五步数据清理、2核2GB容量和T8发布不在本轮范围。

测试和截图见[验收记录](../acceptance/frontend/0.18.1界面问题修复.md)。
