# T3 绑定筛选与异步界面

日期：2026-10-01（Asia/Shanghai）。本批完成绑定台账、默认子操作、F3 和 F5 控制界面，指定枫苑5号-402 真实新增与台账已通过，用户追加的删除绑定另行实施。

## 筛选与公开接口

新增四个同源本人读取接口：

| 方法/路径（/api/v1） | 参数/响应 | 学校来源与边界 |
| --- | --- | --- |
| GET /room-candidates/buildings | FilterChoices：items[].id/label | B05 完整楼栋列表，最多 999 项 |
| GET /room-candidates/floors | 必填 building_id；FilterChoices | B06，楼层 value 按学校页面 split('-')[0] 解析 |
| GET /room-candidates/rooms | 必填 building_id/floor；FilterChoices | B07，id 为学校 roomId |
| GET /room-bindings/{id} | Binding，缓存余额可为 null/stale | 本人当前镜像；非本人或 inactive 为 404，不触发学校查询 |

公开接口由 28 增至 32，源 DTO、OpenAPI、前端类型与契约检查同步。学校主包/三级筛选页已检查，使用指定账号只读定位到唯一枫苑5号-402，B03 roomId 返回相符记录。前端搜索只过滤当前已取得的列表，不向学校发送非空 searchValue；更换父项清空旧子项和候选，迟到响应不能覆盖当前目标。

选定 roomId 后调用现有 GET /room-candidates 再核对；精确 ID 不一致则拒绝，不将搜索分页中的任意记录自动变成可写候选。候选完整学校形状只在 Adapter 的加密 Redis/台账中，浏览器与 Room 仅持短期 candidate_id 和脱敏字段。

## Room 与 Adapter 台账

Room 新 head room_0003 保存 candidate_id、credential_ref/version、binding_status/default_status/default_operation_id。受理先重放本人幂等键，再核验候选并在 preference 锁下登记；同键不同内容 409，同用户/目标未解决操作 409 并返回本人 existing_operation_id。受理响应丢失可保留原键重试；已受理操作不依赖候选仍在缓存。

Adapter 新 head school_0004 保存加密候选和脱敏 confirmed_record，目标比较采用 binary collation，并增加同用户未解决目标唯一屏障。prepared 先查 B02；已绑定直接确认，不发 POST。首次发送前核对持久凭据版本/授权并原子标记 dispatched，随后覆盖当前 school userId，只调用一次 batchAdd。外部请求不持 MySQL 事务锁，学校 POST 不重试。

dispatched 后只查 B02；超时/断连/格式异常/认证错误保持 reconciling，10 分钟未确认转 unknown，并按 5 分钟间隔只回查。进程重启、缓存丢失、暂时空列表、换键均不能再次发送。dispatch 已提交、HTTP 尚未发出时崩溃也保守保持未知，防止用无法证明的“未发送”重写学校关系。

明确学校业务拒绝以 SCHOOL_BINDING_REJECTED 终结；只记录分类，不回显原始 msg。学校成功 code 200 仍须 B02 出现目标才能确认。结果只保留本人目标的楼栋/房号、金额、meter/relation（B02 bruId）等规范字段，清除持久候选密文，不公开住户/学校身份/token。

学校绑定确认后，在 Room 同事务建立 active 镜像、确认状态、room.binding_confirmed 和审计 Outbox。首次无默认创建或接续默认子操作；已有默认新增时保持 unchanged。子操作失败不使已确认学校绑定变为失败，父操作返回 succeeded/confirmed/failed 的分别状态，不能因此重复绑定。

## 前端与控制边界

绑定确认弹窗冻结目标、重复提交合并，持久摘要与原请求键支持刷新/响应丢失恢复；unknown 只查询进度。默认 PUT 保持服务端原默认，202 不提前显示完成，409/响应丢失先读取当前偏好。独立查看使用 URL bindingId，不修改默认/监控；404 清理对象缓存并返回本人列表。

监控设置维护字符串草稿与已保存摘要；后台读取不覆盖编辑，409/响应丢失要明确核对版本和目标。路由离开在本次会话内保留草稿，刷新前提示；默认目标改变时再次确认才允许保存。关闭独立只提交 enabled:false/expected_version，绕过无效的其他草稿，并展示 cancel_pending 和在途发送边界。页面说明控制设置已开放、采集/SMTP 尚未运行；F5-05 仍依赖 T4，不提前勾选。

无新进程；既有 Room Worker 同时扫描默认、绑定和同步。升级先重复运行 upgrade_controls 增加 Room school:binding 权限，再执行 room_0003/school_0004；其他领域权限保持隔离。普通配置的真实绑定写开关仍默认为 false，真实验收仅针对用户明确指定目标临时启用。
