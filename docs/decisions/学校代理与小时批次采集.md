# 学校代理与小时批次采集

版本：0.23.1；日期：2026-11-10（Asia/Shanghai）。0.23.1修正提取参数与租约期限，小时调度沿用0.23.0。

## 目标与配置

学校访问新增可选的易代理出口，默认关闭。开启后，认证、验证码、余额/历史/缴费记录、绑定和建单，以及独立学校支付页共用有效代理。内部服务调用和SMTP沿用各自配置。

在现有部署环境文件中配置：

```dotenv
ELECT_SCHOOL_PROXY_ENABLED=true
ELECT_SCHOOL_PROXY_API_URL=https://api3.ydaili.cn/tools/MeasureApi.ashx?action=EAPI&number=1&orderId=YOUR_ORDER_ID&format=json&type=2&jsonMeta=1111
ELECT_SCHOOL_PROXY_SECRET=YOUR_API_SECRET
```

`API_URL` 原样使用供应商生成链接的地址和查询参数，真实密钥单独放在`ELECT_SCHOOL_PROXY_SECRET`；运行时只拼接或替换`secret=<环境密钥>`，随后直接GET，不增加或覆盖其他参数。`action`、`number`、`format`、`type`、`jsonMeta`均由配置链接决定。示例A池使用`MeasureApi.ashx?action=EAPI`，既有B池`BMeasureApi.ashx?action=BEAPI`同样原样请求。

当前响应解析器需要单条JSON代理，因此公开示例链接本身包含`number=1&format=json&type=2&jsonMeta=1111`：`type=2`选择HTTPS类型，`jsonMeta=1111`请求包含过期时间；这些是示例配置值，运行时不会补齐或改写。返回的 `IP:端口` 以 `http://IP:端口` 配置HTTP CONNECT，无代理用户名、密码或其他认证步骤。提取地址支持HTTP/HTTPS，示例使用HTTPS；供应商出口白名单按其订单要求配置。

成功响应按[易代理公开文档](https://www.ydaili.cn/aspx/hbapi.aspx)的 `status="success"`、`data=[{"ip":"...","port":整数,"expire_time":"2026-05-13 17:11:23"}]` 解析，仅接受一条公网IPv4和有效端口。`expire_time`是可选的IP过期时间字符串；配置和供应商响应在入口校验，缓存保存已解析租约。

开关只接受 `true/false`。开启但URL/密钥缺失时启动失败；关闭时无需填写。按用户本轮要求，提取密钥通过环境变量仅传Adapter，其他服务只读取开关。公开模板只保留占位值，真实环境文件保持Git忽略；配置、完整请求URL、供应商响应与异常原文均不写日志。查看Compose使用 `config --quiet`，不打印展开后的敏感环境配置。

## 获取时间、复用与换IP

现有Adapter Redis命名空间共享代理租约，包含地址、`acquired_at` 和 `expires_at`，时间为UTC Unix秒。优先将供应商`expire_time`转换为绝对到期时间；无时区的日期时间按`Asia/Shanghai`解释，显式时区按其偏移换算。供应商未返回该字段，或值为`null`/空字符串时，才使用开始提取时间加60秒。0.23.1替代原55秒上限，不截短供应商有效期，也不将较短有效期延长到一分钟。

提取耗时计入有效期，Redis TTL使用发布时距`expires_at`的剩余毫秒。已到期或非空但无法解析的时间按供应商失败处理，返回可重试503且不缓存，不使用一分钟覆盖错误的到期信息。到期由下一次学校请求自动提取，不空闲定时消耗额度。

并发请求通过Redis短锁共用一次成功提取和同一有效IP。失效时比较完整租约删除，旧请求失败不能删除新租约。提取整体最多5秒，并纳入原学校操作总预算；超时、格式错误、空列表或拒绝返回可重试的 `503 DEPENDENCY_UNAVAILABLE`。供应商失败不缓存成功租约，等待者后续可以重新提取。

学校连接错误、连接/读写超时、异常断流或 `407/502/503/504` 响应使当前代理失效。验证码/普通只读请求与学校支付页GET可在同一总预算内至多换一个代理再试；响应体中断由既有只读恢复路径处理。原有学校查询重试仍受总预算约束。

学校 `401/403` 继续原认证处理，`429` 继续原全校冷却，不通过换IP绕过限流。认证提交、绑定/解绑、建单和支付表单POST不自动重放，沿用原台账与unknown/回查规则。开启代理后提取失败不会自动直连。

学校域名、路径和逐跳重定向限制保持；代理模式由代理解析学校域名，HTTPS目标主机名、SNI和证书校验保持。直连仍使用原公网DNS校验与固定IP连接；支付站点原本获准的HTTP路径沿用原规则。

## 定时采集按小时合批

仅开启代理时改变调度：北京时间某自然小时内，首个有效账号计划到点后，一并受理该小时结束前其他有效账号的定时查询。例如10:05到点，会一并受理10:20、10:50的计划，11:00的留到下一小时。无到期任务时不提前触发，手动采集自身也不启动小时批次。

各账号保留原时间锚点；提前采集使用原 `next_run_at` 作为 `scheduled_for`，下一次为原计划加监控间隔。到期/积压账号以本小时结束前的最近逻辑槽折叠，合并旧槽与本小时待触发槽，只受理一次；较长间隔在本小时没有槽时仍使用最近旧槽。例如10:10启动、原60分钟锚点09:20，会受理10:20槽并推进11:20，完成后续批也不重复。关闭、授权失效、凭据切换、generation、绑定、active run合并与提交栅栏保持。

每个调度事务最多处理100账号。首个真实到期run的合法 `monitor.run_ready` 唤醒使用确定的小时事件ID，作为Outbox续批标记，与任务和计划同事务提交；后续tick或重启可继续受理超过100个的本小时剩余计划。手动run不创建标记，无新表或迁移。

代理模式Worker使用4个共享槽，直连保留2个。独立心跳、45秒租约、10秒续租、90秒执行预算与停止领取/在途drain保持；学校全局5、后台4、交互预留1和数据库池不变。批次持续按4槽并发执行；超过代理有效期或出口失效时更新IP，不保证整个小时只提取一个IP。

## 部署与验证范围

无需数据库迁移、业务Secret文件升级或新增容器。更新配套镜像和环境配置后，通过原升级入口重建Adapter与Monitoring（core模式重建核心）加载开关；现有部署本轮未升级。恢复隔离覆盖显式关闭代理并清空Adapter提取地址/密钥，原无外发与停后台约束保持。

0.23.0定向验证使用合成供应商响应、假学校传输与WSL独立MySQL8.4；0.23.1使用合成供应商响应验证期限优先级、时区、剩余TTL及URL参数原样保留/不补齐，具体结果见[PROJECT_PROGRESS.md](../../PROJECT_PROGRESS.md)。0.23.1对用户提供链接执行一次直接GET，仅返回供应商`code/info`，未取得成功租约，不记录响应原文；本轮未运行真实学校登录、查询、支付或邮件验收。
