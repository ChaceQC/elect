# 运行状态与容量

日期：2026-10-03；版本：0.13.1。

## 当前部署停机状态

2026-10-03按用户要求停止本项目当前Docker部署。使用原`.env.local`、三份编排和`elect-local`项目名执行：

```sh
docker compose --env-file deploy/.env.local \
  -f deploy/compose.yaml -f deploy/compose.local.yaml \
  -f deploy/compose.smtp-direct.yaml -p elect-local stop --timeout 30
```

命令成功退出，31个长期服务均已停止；连同此前成功退出的migrate，保留的32个容器全部为exited。本项目历史测试/恢复环境继续停止，所有elect项目运行容器数为0。MySQL、Redis、RabbitMQ三个原数据卷与容器均保留，其他五个运行中的非本项目容器ID未变。

网页入口6874和SMTP定向通道16874均无TCP监听，原`/healthz`连接失败（curl返回码7、HTTP 000）。停机期间网页、后台采集和邮件处理不可用；数据库内配置、待处理任务和订单台账保留，恢复部署后仍按既有持久恢复机制处理。当前保持停止，恢复时使用同一env、项目名和三份编排，先校验配置再显式启动及检查健康。

下文2026-10-02的资源采样为历史运行记录，不能作为当前停机后的资源占用。

## 容器与权限

基础编排的30个长期服务与migrate/tls-check作业见deploy/compose.yaml；本机elect-local另运行smtp-direct，共31个长期容器：

| 组 | 入口/权限 | 健康依据 |
| --- | --- | --- |
| Nginx、MySQL、Redis、RabbitMQ（4） | 静态/API反代；独立数据网络/卷；仅正式Nginx发布80/443 | 入口检查、SQL/缓存/消息探测 |
| Gateway、七域API（8） | services.gateway/identity/school_adapter/room/monitoring/payment/notification/audit；Gateway无DB，各域app账号 | 当前迁移head、MySQL与MQ/Redis降级 |
| 六域Relay、Audit Worker（7） | services.common.job；本域Outbox/Inbox、签名与最小MQ权限 | 真实扫描/确认/提交心跳 |
| Identity恢复、Room同步、School维护（3） | services.common.business_worker；Room另执行默认/绑定/查询 | 实际扫描与持久推进 |
| 监控Scheduler/Worker/恢复/提醒（4） | services.monitoring.job；只有明确目标当前代次执行 | 持久计划/租约/结果心跳 |
| 邮件Worker/恢复（2） | services.notification.job；仅发送Worker有notification_egress | DATA边界、job/许可/未知恢复 |
| Payment Worker/恢复（2） | services.payment.process；经Adapter学校出口 | 租约、永久发送标记和安全回查 |

所有应用UID10001、只读文件系统、独立Secret；恢复/备份/status为显式ops作业，业务进程不持有全域DDL。School出口只给Adapter，SMTP出口只给发送Worker。后台last_success在20秒内才健康，不用空循环报告。

## 查看状态

```sh
sh deploy/status.sh /absolute/deploy/.env elect
```

输出容器健康/资源、各域结构版本/Outbox积压、绑定/上游未知、监控计划/运行、邮件和订单分类、MySQL当前/最高连接/慢查询、队列ready/unack/consumers与数据库卷空间；不输出账户、邮箱、学校ID、金额或载荷。Monitoring已有签名内部GET /internal/v1/monitor/metrics，不能公开代理到浏览器。

关注计划延迟、最老任务、长期unknown、采集新鲜度、DATA后未知、心跳中断和磁盘余量。MySQL不可用停止新派发/提交；MQ失效继续MySQL扫描，Redis失效不退回进程字典。学校429使用持久延期与全局冷却，不靠增加Worker突破限制。

## 当前预算与实测

0.15.0完成[Docker低资源部署优化方案](../Docker低资源部署优化方案.md)第二步七域轻量组合，基础长期容器30→13、Python进程26→9。API健康列出独立`background_roles`，意外退出/过期角色返回503；MQ故障时数据库扫描继续推进且显示degraded。统一入口及恢复禁用见[生命周期决策](../decisions/Docker低资源后台生命周期.md)。本机两次隔离CLI快照为30容器2623.91MiB、13容器1376.16MiB，详见[第二步验收](../acceptance/Docker低资源第二步验收.md)；这些单次样本不包含OCR/负载/备份峰值与宿主机开销，不是2GB容量证据。下文原业务历史资源记录保留原口径。

0.16.0第三步在combined固定每池2+1、8池理论24条应用连接/MySQL上限40；standalone保留2+3、25池理论125条/上限200。生效参数、旧Secret兼容、OCR和Docker探针预算见[资源决策](../decisions/Docker低资源资源参数.md)。运行状态补充连接上限错误与磁盘临时表计数；不能把空闲连接数当作峰值预算。

学校共享并发最多5、后台最多4，保留交互通道；每账号并发1。间隔60–1440分钟；真实学校频率上限未确认，不据模拟吞吐扩大开放人数。当前仅内部指定验收账号，学校写/SMTP/支付仍依验收标志和开关。

本轮100计划、两Scheduler、8个同进程并发执行，30ms模拟学校，实际MySQL/Redis/MQ：调度0.376秒、采集1.806秒（55.36样本/秒）、attempt p95 0.255秒；101请求（含1个交互探测）峰值并发5，100签名唤醒经confirm/Inbox，单run一条样本。内存峰值114740KiB；OCR冷加载1.034秒/107964KiB，无学校请求，低于Adapter的1024MiB上限。

这些数值仅描述测试机器、单轮和指定延迟，不能替代全天100用户或真实学校限流验收。备份容量随MySQL数据/binlog增长，检查snapshot/binlogarchive大小和异机留存；本轮小样本数据库分配量与运行状态见T7验收JSON，不直接外推年度磁盘量。
