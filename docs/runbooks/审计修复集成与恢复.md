# 审计修复集成与恢复

日期：2026-10-06（Asia/Shanghai）。适用版本0.20.1；[执行计划](../审计修复执行计划-2026-10-06.md)第13节，验收见[R7](../acceptance/审计修复/R7集成兼容与恢复.md)。

## 恢复顺序与观测水位

继续使用`deploy/backup.sh`和`deploy/restore.sh`。目标必须是独立`elect-restore-*`项目，空库、内部网络、无外发且所有profile应用停止。Secret随同一备份集独立安全传递，不能重新provision覆盖密码或混用其他备份的密钥。目标机仍只需要Docker Engine/Compose。

恢复apply先校验七域归档载荷和冷索引，撤销会话、暂停后台、保留支付/邮件unknown并隔离旧Outbox；最后比较Adapter的`balance_observation_counters.sequence`与Room每owner全部绑定缓存的`observation_sequence`、`last_success_sequence`、`last_error_sequence`最大值。每批250个owner，游标续读，不按学校时间排序；历史无序号缓存不伪造高水位。仅维护进程使用各域原DDL账号的两个单连接池，业务2+1池、学校5/4/1预算不变。

计数缺失或小于缓存高水位时，恢复命令非零退出，所有已完成隔离保持，不能启动正常后台或解除出口限制。核对来源是否为同一完整备份集，优先重建另一个空恢复目标并恢复一致备份；不得清空缓存序号、计数归零或盲目抬高计数掩盖不一致。本版本没有自动修正水位命令。修正备份来源后重新运行apply可重入。

## 升级与回退

0.20.1不新增迁移、Secret或公开API。沿用R1—R6的七域最新迁移；升级统一停止本项目所有旧profile角色，再迁移并启动所选core/combined/standalone模式。不得混跑新旧观测写者、归档去重逻辑或领取协议；保留原Secret和卷。

回退候选须识别R4冷标识及R2观测序号，回退旧镜像不能修复旧版已知缺陷。0.20.0缺少本次恢复水位门禁，不用其恢复入口替代0.20.1；未知副作用、原始样本、修复别名和冷索引不能删掉以配合回退。生产升级、存量apply和发布须另按目标和维护窗口执行，本轮均未执行。
