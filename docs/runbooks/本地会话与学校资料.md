# 本地会话与学校资料

## 接口与权限

R6新增`GET /api/v1/auth/session`，返回`LocalSession`：真实本地用户`id`、内存CSRF和本库同意记录。内部`POST /internal/v1/browser/session`沿用`identity:browser`签名权限及`BrowserSession`命令，由Identity校验token、用户状态、session_version、滑动有效期和绝对有效期；不依赖Adapter。无Cookie或真实会话失效返回401，本库/同意记录不可用返回503，不能根据Cookie存在就宣告登录。

旧`/auth/me`与登录`LoginResult.user`结构保持完整Me，学号、学校及credential_status只能从Adapter资料取得。没有向Identity复制学号或凭据，没有增加Secret、连接池或数据库迁移。core静态分派与独立HTTP共用同一身份依赖；携带签名用户上下文时仍核对归属。

## 前端与回退

本地会话与学校资料分别加载；本地会话成功即可进入缓存页面。学校资料不可用时显示暂不可用，不能伪造Me、学号或认证状态；真正401仍退出。学校相关操作受限，本地缓存/历史、已受理操作读取和关闭监控保持原服务端授权与数据质量标识。

新前端只有新端点明确404时才在本次Provider生命周期内切换旧`/auth/me`兼容路径；503不触发兼容或两个接口循环请求。资料响应须通过当前用户、请求代次及API epoch检查，不能用迟到资料切换账号或覆盖本地CSRF。BroadcastChannel、跨账号缓存清理和成功登录后的协议阅读记忆保持。

新增接口为兼容增量，优先回退前端；现有部署不会随源码自动升级。后端旧Me仍可供旧前端使用，新前端在旧后端仍依赖旧Me的在线能力，不能宣称旧后端也获得离线解耦。完整集成与部署升级另按R7和明确授权执行。
