## Secret 与升级

已有 T4 部署重复执行 services.deployment.upgrade_controls，增加 notification_encryption_key_bundle、不可用的 smtp_credentials 占位文件及服务/MQ 最小权限。保留旧密钥、连接凭据与所有未知台账；迁移 monitoring_0005、notification_0002 后重建 RabbitMQ 和受影响应用，加载原子替换后的 Secret。

smtp_credentials 是 JSON Secret，字段为 host、port、sender、username、password、tls（implicit 或 starttls）；可选 proxy_url（HTTP CONNECT 代理地址，包含认证时也属于 Secret）。不要在终端打印或写入公开 .env；默认占位配置不能作为真实发送配置，ELECT_ALLOW_REAL_SMTP 默认 false。仅 Notification 挂载本域邮箱密钥和 SMTP Secret，邮件 Worker 有独立外网网络。

本地 email_auth.txt 的五行格式及禁止直接读取约束见 [开发说明](../开发说明.md#本地真实测试凭据)。私有 auth.txt 不改变权限、不复制；专用宿主进程在内存解析，经匿名 stdin 交给受限容器，命令行与日志不含密码。email_auth.txt 由专用验收进程在内存解析。

## 连接与代理

- 先运行 `python -m scripts.smtp_connection_probe --email-auth-file /absolute/email_auth.txt`；只检查连接/TLS，不认证、不发正文，输出分类结果。
- SMTP 直接 TCP 不自动继承 HTTP_PROXY/HTTPS_PROXY。即使这些变量为空，Clash TUN 仍可透明代理。使用 smtp_proxy_probe 只在内存读取代理配置，并通过本机控制器核对目标连接的路由类别，不输出 SMTP 地址、节点密钥或控制器 Secret。
- 本次已确认 TUN 的 Match/PROXY 路由失败而物理网卡直连成功。后续本地验收可在专用隔离项目使用 t5_live_runner 的 --direct-interface，通过短期、随机认证、只限指定 SMTP 的通道执行；需要宿主允许绑定该物理网卡。该选项仅用于验收，不修改系统代理、不为生产容器增加权限。
- 正式部署使用可达的 SMTP 直连网络或明确配置的 HTTP CONNECT 代理；TLS 始终校验最终 SMTP 证书，不能用关闭校验解决代理问题。

## 失败与恢复

连接/认证/信封阶段错误可从脱敏 error_code 区分；明确临时拒绝最多三次重试，1/5/15 分钟，仍须新鲜样本和新许可。永久拒绝或耗尽显示 email_failed，当前事件不反复补建失败提醒；修改邮箱或重新启用后由新样本重新判断。

正文前进程丢失可安全释放旧许可并重试；正文边界后丢失保持 unknown。关闭或撤回只阻断尚未取得许可的发送，已获许可的在途邮件可能完成。MySQL/Monitoring 不可用时禁止绕过许可或本域落库直接外发。
