# 本机私网 HTTP 部署

日期：2026-10-02；版本：0.13.1。按用户本轮要求，入口为 `http://10.8.0.88:6874`，暂不配置域名或入口证书。后端内部 TLS 和 SMTP TLS 继续校验。

0.15.0提供统一`compose.sh`/`upgrade.sh`入口；第一次采用时，公开env须显式设置`ELECT_SMTP_DIRECT_ENABLED=true`才能加载本机定向通道，`ELECT_ALLOW_LOCAL_HTTP=true`选择私网覆盖，`ELECT_DEPLOYMENT_MODE=combined`选择13容器组合（含本机通道为14个）。默认模板仍为standalone且通道关闭；原本机env/卷/部署本轮保持停机。已有卷切换通过upgrade先停全部旧角色，不重新provision；细节见[低资源生命周期](../decisions/Docker低资源后台生命周期.md)。下文保留0.13.1原部署记录与入口。

## 配置与启动

本机须有指定 IPv4（本轮为 awg0 的 10.8.0.88），只需 Docker Engine/Compose。使用独立项目 elect-local 和新 Secret/数据卷，普通业务从空状态开始，学校绑定通过真实登录后只读同步，不导入验收夹具。

```sh
cp deploy/.env.local.example deploy/.env.local
chmod 600 deploy/.env.local
docker build -t elect-backend:v0.13.1 backend
docker build -t elect-frontend:v0.13.1 frontend
mkdir -p /opt/elect-local/secrets
chmod 700 /opt/elect-local /opt/elect-local/secrets
docker run --rm --network none --user 0:0 \
  -v /opt/elect-local/secrets:/run/provision elect-backend:v0.13.1 \
  python -m services.deployment.provision --output-dir /run/provision
docker run --rm --network none --user 0:0 \
  -v /opt/elect-local/secrets:/run/upgrade elect-backend:v0.13.1 \
  python -m services.deployment.upgrade_controls --directory /run/upgrade
```

首次 provision 拒绝非空目录；已有部署保留 Secret 和卷。配置模板默认关闭外部写操作和 SMTP；本轮用户指定使用本地邮件文件后明确开启本机 SMTP；根据绑定页反馈，本机同时将 ELECT_ALLOW_SCHOOL_BINDING_WRITES 设置为 true 供用户在页面确认后新增/解绑，支付验收标志仍为 false。

不需要邮件直连通道的环境使用 base/local 两份编排。本机有透明 TUN 代理，使用下一节的 smtp-direct 覆盖：

```sh
docker compose --env-file deploy/.env.local \
  -f deploy/compose.yaml -f deploy/compose.local.yaml \
  -f deploy/compose.smtp-direct.yaml -p elect-local config --quiet
docker compose --env-file deploy/.env.local \
  -f deploy/compose.yaml -f deploy/compose.local.yaml \
  -f deploy/compose.smtp-direct.yaml -p elect-local up -d --no-build --wait
```

Nginx 只发布指定 IPv4 的 6874，所有 API/数据库/Redis/RabbitMQ 保留内部网络；不发布 80/443。TLS 入口预检在 local 覆盖中移入未启用的 tls profile，Nginx 不挂载入口证书。默认 HTTPS 编排继续通过域名/证书预检，缺失证书时 `/dev/null` 仅作为不可用引用，不能启动有效 HTTPS 入口。

ELECT_ALLOW_LOCAL_HTTP=true 只接受与 ELECT_HTTP_BIND/ELECT_HTTP_PORT 完全相同的私网 IPv4 来源，拒绝通配地址、公网 IP、错误端口和路径。HTTP 的 Cookie 为 elect_session_local/elect_browser_local，HttpOnly/SameSite=Lax/Path=/，不设 Domain；HTTPS 保留 __Host-elect_session/__Host-elect_browser 和 Secure。Origin 与内存 CSRF 仍校验，协议与登录响应 no-store。

浏览器 HTTP 环境没有 crypto.randomUUID；请求标识、幂等意图和快照修订使用 getRandomValues 生成 UUID v4。HTTPS 可用原生 randomUUID 时沿用原生实现。

本机历史验收网络占用 Docker 默认地址池，因此 local 编排使用五个 10.240.0.0/24–10.240.4.0/24 小网段；若与目标网络冲突，在 .env.local 中覆盖 ELECT_LOCAL_EDGE_SUBNET/APP_SUBNET/DATA_SUBNET/SCHOOL_SUBNET/NOTIFICATION_SUBNET。

## 指定邮件配置与代理直连

email_auth.txt 由专用配置进程在内存解析，不在终端直接预览。前三行是发件地址/SMTP 服务/端口，第四行密码原样保存，第五行是专用验收收件人；SMTP 导入不生成提醒，不向第五行自动发信。文件和 Secret 均限制权限，不能提交 Git。

```sh
chmod 600 email_auth.txt
docker run --rm --network none --user 0:0 \
  -v /opt/elect-local/secrets:/run/configure \
  -v "$PWD/email_auth.txt:/run/email_auth.txt:ro" elect-backend:v0.13.1 \
  python -m services.deployment.configure_smtp \
  --email-auth-file /run/email_auth.txt --directory /run/configure \
  --direct-interface enp2s0 --proxy-bind 172.17.0.1 --proxy-port 16874
```

在本地 .env.local 中显式设置 ELECT_ALLOW_REAL_SMTP=true 后启动前述三份编排。邮件目的地址由用户保存的监控邮箱决定；启用监控后仍须满足新鲜低余额样本、提醒次数、发送许可与持久 job 边界。

SMTP Worker 经独立随机认证 CONNECT 通道，只允许 Secret 中那个 SMTP 主机及端口；通道仅监听 Docker 网桥 172.17.0.1:16874，出口绑定 enp2s0，以加密 DNS 查询实际公网目标。通道不持有 SMTP 账号密码，Worker 校验最终 SMTP 证书并完成认证；不改变全局代理规则或学校访问路径。宿主模式只用于该定向通道，权限为 NET_RAW，无数据库/应用 Secret。

首次直连 Secret 拒绝覆盖；更改 SMTP 或网卡时停止 Notification Worker 和通道，保留配置备份，再显式配置新 Secret 并重建受影响容器，避免旧挂载或在途任务混用。SMTP 的 sent 仍仅表示服务器接受，最终收件另行确认。

## 检查与启停

```sh
curl --noproxy '*' http://10.8.0.88:6874/healthz
docker compose --env-file deploy/.env.local \
  -f deploy/compose.yaml -f deploy/compose.local.yaml \
  -f deploy/compose.smtp-direct.yaml -p elect-local ps -a
```

预期为 31 个长期服务健康，migrate 成功退出，tls-check 不运行。重复 up 可执行幂等迁移；restart 和普通 down 不删除数据卷。启停、重建均须使用同一 env、项目名和三份编排，不使用 down -v。

浏览器专用检查 frontend/scripts/local-browser.mjs 使用生产 Nginx/真实学校只读，凭据仅在进程内存，不截图/trace/打印原始响应；验证码由隔离后端容器 OCR 后通过受限本机文件交回，不替换学校验证码。检查结束注销测试应用会话，保留学校同步出的实际绑定和默认寝室，不自动开启监控或触发学校写入。

本轮只检查邮件连接、最终 SMTP TLS 和账号认证，不自动发送测试正文；既有 T5 的指定邮箱真实接受/收件证据单独保留。新部署结果见 PROJECT_PROGRESS.md。支付 D02 自动终态、异机/PITR 和 T8 发布仍按原计划待验。

绑定页历史“受理未确认”可逐条选择“停止本地重试”，再同步学校绑定核对；此操作不发送/撤销学校请求。明确FEATURE_DISABLED拒绝不会再留下待确认记录，依赖失败/网络未知仍保留原幂等键。普通模板写开关仍false；本机实际env按用户反馈为true，不自动执行任何绑定或解绑。

0.13.1成功同步直接以学校列表覆盖当前绑定，历史保留；原默认仍在就保持，否则按学校返回顺序选第一间，空列表清空默认及监控目标。失败/异常响应继续保留原数据；再次同步即可将旧rechecking记录移出当前列表。
