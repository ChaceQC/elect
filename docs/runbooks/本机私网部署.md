# 本机私网 HTTP 部署

日期：2026-10-04（Asia/Shanghai）；版本：0.18.1。按用户要求拉取最新 `dev` 并恢复本机部署，入口为 `http://10.8.0.88:6874`，暂不配置域名或入口证书。后端内部 TLS 和 SMTP TLS 继续校验。

当前本机配置使用 `ELECT_IMAGE_MODE=local`、`ELECT_DEPLOYMENT_MODE=combined`、`ELECT_ALLOW_LOCAL_HTTP=true` 和 `ELECT_SMTP_DIRECT_ENABLED=true`，共14个长期容器。0.18.1从当前dev源码构建，两张镜像记录相同版本及源提交；这次本机部署不代表该版本已完成CI发布。发布摘要镜像使用[固定镜像手册](固定镜像发布与启动.md)中的start/upgrade入口；本机源码开发版通过统一compose.sh按依赖串行启动。

已有卷切换先加密备份，停止全部旧应用/profile角色，再离线升级既有权限并重建RabbitMQ；保留原Secret和三个数据卷，不重新provision。组合与退出规则见[低资源生命周期](../decisions/Docker低资源后台生命周期.md)。combined同时选择共享池、MySQL预算及RabbitMQ核心定义导入，见[资源决策](../decisions/Docker低资源资源参数.md)；既有绑定确认事件的权限升级见[执行效率决策](../decisions/Docker低资源执行效率.md)。

## 配置与启动

本机须有指定 IPv4（本轮为 awg0 的 10.8.0.88），只需 Docker Engine/Compose。使用独立项目 elect-local；首次部署从空状态开始，已有部署沿用原配置、Secret和数据卷，不导入验收夹具。下面的复制模板和provision仅用于首次部署。

```sh
cp deploy/.env.local.example deploy/.env.local
chmod 600 deploy/.env.local
task_revision=$(git rev-parse HEAD)
docker build --build-arg ELECT_BUILD_VERSION=v0.18.1 \
  --build-arg ELECT_BUILD_REVISION="$task_revision" -t elect-backend:v0.18.1 backend
docker build --build-arg ELECT_BUILD_VERSION=v0.18.1 \
  --build-arg ELECT_BUILD_REVISION="$task_revision" -t elect-frontend:v0.18.1 frontend
mkdir -p /opt/elect-local/secrets
chmod 700 /opt/elect-local /opt/elect-local/secrets
docker run --rm --network none --user 0:0 \
  -v /opt/elect-local/secrets:/run/provision elect-backend:v0.18.1 \
  python -m services.deployment.provision --output-dir /run/provision
docker run --rm --network none --user 0:0 \
  -v /opt/elect-local/secrets:/run/upgrade elect-backend:v0.18.1 \
  python -m services.deployment.upgrade_controls --directory /run/upgrade
```

首次 provision 拒绝非空目录；已有部署保留 Secret 和卷。配置模板默认关闭外部写操作和 SMTP；本轮用户指定使用本地邮件文件后明确开启本机 SMTP；根据绑定页反馈，本机同时将 ELECT_ALLOW_SCHOOL_BINDING_WRITES 设置为 true 供用户在页面确认后新增/解绑，支付验收标志仍为 false。

本机有透明TUN代理，统一入口按上述显式配置加载local、combined和smtp-direct覆盖。首次启用通道先完成下一节的邮件Secret配置，再设置上述部署选择字段。源码镜像构建和已有权限升级完成后，预检入口并按基础服务→迁移→领域→邮件通道/Worker→入口依次等待：

```sh
set -eu
compose() {
  sh deploy/compose.sh "$PWD/deploy/.env.local" elect-local --parallel 1 "$@"
}
compose config --quiet
compose run -T --rm --no-deps nginx nginx -t
for task_service in mysql redis rabbitmq; do
  compose up -d --no-build --no-deps --wait --wait-timeout 180 "$task_service"
done
compose run -T --rm --no-deps migrate
for task_service in school-adapter monitoring identity room notification payment audit gateway \
  smtp-direct notification-worker nginx; do
  compose up -d --no-build --no-deps --wait --wait-timeout 180 "$task_service"
done
```

Nginx 只发布指定 IPv4 的 6874，所有 API/数据库/Redis/RabbitMQ 保留内部网络；不发布 80/443。TLS 入口预检在 local 覆盖中移入未启用的 tls profile，Nginx 不挂载入口证书。默认 HTTPS 编排继续通过域名/证书预检，缺失证书时 `/dev/null` 仅作为不可用引用，不能启动有效 HTTPS 入口。

ELECT_ALLOW_LOCAL_HTTP=true 只接受与 ELECT_HTTP_BIND/ELECT_HTTP_PORT 完全相同的私网 IPv4 来源，拒绝通配地址、公网 IP、错误端口和路径。HTTP 的 Cookie 为 elect_session_local/elect_browser_local，HttpOnly/SameSite=Lax/Path=/，不设 Domain；HTTPS 保留 __Host-elect_session/__Host-elect_browser 和 Secure。Origin 与内存 CSRF 仍校验，协议与登录响应 no-store。

浏览器 HTTP 环境没有 crypto.randomUUID；请求标识、幂等意图和快照修订使用 getRandomValues 生成 UUID v4。HTTPS 可用原生 randomUUID 时沿用原生实现。

本机历史验收网络占用 Docker 默认地址池，因此 local 编排使用五个 10.240.0.0/24–10.240.4.0/24 小网段；若与目标网络冲突，在 .env.local 中覆盖 ELECT_LOCAL_EDGE_SUBNET/APP_SUBNET/DATA_SUBNET/SCHOOL_SUBNET/NOTIFICATION_SUBNET。

## 指定邮件配置与代理直连

email_auth.txt 由专用配置进程在内存解析，不在终端直接预览。前三行是发件地址/SMTP 服务/端口，第四行密码原样保存，第五行是专用验收收件人；SMTP 导入不生成提醒，不向第五行自动发信。文件和 Secret 均限制权限，不能提交 Git。

```sh
chmod 600 email_auth.txt
docker run --rm --network none --user 0:0 \
  -v /opt/elect-local/secrets:/run/configure \
  -v "$PWD/email_auth.txt:/run/email_auth.txt:ro" elect-backend:v0.18.1 \
  python -m services.deployment.configure_smtp \
  --email-auth-file /run/email_auth.txt --directory /run/configure \
  --direct-interface enp2s0 --proxy-bind 172.17.0.1 --proxy-port 16874
```

在本地 .env.local 中显式设置 ELECT_ALLOW_REAL_SMTP=true 和 ELECT_SMTP_DIRECT_ENABLED=true 后使用统一入口启动。已有部署保留邮件Secret，本轮重部署不重新读取email_auth.txt。邮件目的地址由用户保存的监控邮箱决定；启用监控后仍须满足新鲜低余额样本、提醒次数、发送许可与持久job边界。

SMTP Worker 经独立随机认证 CONNECT 通道，只允许 Secret 中那个 SMTP 主机及端口；通道仅监听 Docker 网桥 172.17.0.1:16874，出口绑定 enp2s0，以加密 DNS 查询实际公网目标。通道不持有 SMTP 账号密码，Worker 校验最终 SMTP 证书并完成认证；不改变全局代理规则或学校访问路径。宿主模式只用于该定向通道，权限为 NET_RAW，无数据库/应用 Secret。

首次直连 Secret 拒绝覆盖；更改 SMTP 或网卡时停止 Notification Worker 和通道，保留配置备份，再显式配置新 Secret 并重建受影响容器，避免旧挂载或在途任务混用。SMTP 的 sent 仍仅表示服务器接受，最终收件另行确认。
