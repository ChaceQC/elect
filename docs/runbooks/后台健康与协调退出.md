# 后台健康、诊断与协调退出

日期：2026-10-06（Asia/Shanghai）；源码版本0.19.5。阶段门禁和真实证据见[R3验收](../acceptance/审计修复/R3诊断健康与失败恢复.md)。

## 分派诊断

core直接分派和独立HTTP入口共用异常字段白名单：service、domain、登记路由name、request_id、duration_ms、exception_type和整数database_error。数据库错误码保留MYSQL_编号，其他仅保留代码定义的异常类别；外部仍返回原503安全错误信封。

内部客户端转发UUID请求ID，身份验证后以签名中的request_id覆盖关联ID。路由取登记名称，不记录原始路径或查询串。ApiError继续传递原安全业务结果；未处理错误只在实际执行边界记录一次，调用层不重复打印底层异常。

禁止记录exception repr/str、SQL/参数、请求正文、JWT、Cookie、学校响应原文、密文和支付票据。需要诊断时按request_id筛选领域和登记路由，再看异常类别/编号，不打开业务Secret或原始学校载荷。

## 统一健康语义

core/combined的HTTP探针、独立Worker文件探针和进程监督器共用`health_state.assess`。`last_tick`、`last_success`及UTC展示时间与单调时钟判定分开，墙上时钟回拨不延长预算。每角色保留20/45秒失活窗口；监控两个执行槽在同一worker心跳的slots中独立判定，任一槽持续失败不能被另一槽的成功覆盖。

- 成功的持久扫描/提交，包括空队列扫描，才更新业务成功时间并清除连续失败。`tick()`只证明循环/数据库连接仍响应，普通SELECT 1不能刷新业务成功或清掉错误。
- 连续失败从第一次未处理的业务扫描错误开始，60秒内显示degraded并允许恢复；达到预算返回not_ready/503。没有在途、计划扫描或业务成功而只tick的循环也不能永远健康。Adapter正常60秒清理间隔有原心跳窗口的调度余量；首次失败另起连续失败预算。
- 在途记录期限、最近有效续租和租约有效期；续租只能在真实数据库更新成功后记录，不刷新业务成功。历史提交取得防接管行锁后改由事务与原90秒期限保护；工作完成到写入扫描结果之间留1秒交接窗口，不能以此重置连续失败。
- MQ明确连接/接收/发布失败与业务SQL错误分开。Relay/Audit在MQ不可用时仍扫描本域Outbox/Inbox，其他消费者继续持久领取；扫描成功可HTTP200/degraded，恢复后ready。SQL持续失败不能被MQ重连或通用探针掩盖。

## fatal、停止和容器恢复

每个启用后台的进程只有一个`ProcessControl`。角色意外return/raise/cancel、失活、在途超期、持续失败超预算或OCR真实计算超过调用期限加5秒余量，触发一次脱敏`process_fatal`（领域/角色/原因）。先停止本进程全部新领取，再驱动ManagedServer结束和领域drain；core停止所有领域，combined停止本域，standalone使用相同角色监督器。恢复环境`ELECT_BACKGROUND_ENABLED=false`不创建角色或监督线程。

独立daemon监督线程不依赖事件循环推进，也不占用业务连接。drain耗尽后取消剩余任务，再留最多5秒完成退出；事件循环/任务不响应取消时最终`os._exit(1)`，不依赖Docker杀死unhealthy容器。OCR关闭最多等待原5秒，仍有原生计算时通知fatal并保留最终退出保障，不能在解释器等待ThreadPool线程前撤掉保障。正常SIGTERM关闭完成后撤销监督，退出0；不可恢复失败退出1。

| 入口 | drain预算 | Compose停止宽限 |
| --- | --- | --- |
| core | 180秒，各域从同一次stop起按自身预算drain | 195秒 |
| combined Identity / Room | 125秒 | 135秒 |
| combined Monitoring | 100秒 | 110秒 |
| combined Payment | 180秒 | 190秒 |
| combined Adapter / Notification / Audit | 30秒 | 40秒 |
| standalone API、Relay/Audit和普通短扫描进程 | 30秒 | 40秒 |
| standalone Identity恢复 / Room任务 | 125秒 | 135秒 |
| standalone Monitoring Worker / Payment Worker | 100 / 180秒 | 110 / 190秒 |
| 独立邮件发送 | 30秒 | 原45秒 |

保留既有`restart: unless-stopped`，无需autoheal或新守护容器。停止不清空租约、不重置epoch、不把unknown改回待发送。重启由原持久领取、D01 dispatched、邮件DATA标记及Inbox/Outbox规则恢复；支付/解绑2秒正常回查与失败30秒不变。

## 升级、回退与验证

无业务表迁移；不增加连接池、学校并发、长期容器或副作用开关。现有部署、业务存量与发布均不随源码变更自动执行。

升级沿用统一入口，先停止目标项目全部旧profile角色，再使用0.19.5代码和配套Compose宽限启动。七域迁移头仍为R2的school_0007、room_0006及其余既有head；不执行存量修复命令。回退须将诊断、健康判定与退出联动作为整体评估，不能只保留新探针而撤掉退出保障。

隔离入口为`deploy/test-r3-processes.sh`（一次性MySQL、三种真实入口容器自动重启、租约与模拟发送标记）和`deploy/test-r3-transport.sh`（实际MQ停止65秒与恢复）。两者均使用独立内部网络、临时数据库和合成载荷，无业务Secret/真实学校/SMTP/支付；进程子测试为`tests/unit/test_process_exit.py`。完整CI的compatibility组纳入前一个入口，quick仍只执行前后端规定门禁。
