# 请求预算与保留归档

日期：2026-10-06。0.19.6，R4实施记录；现有部署未升级。

## 受理与恢复

同owner的余额刷新和二维码刷新分别每分钟6个新键、滚动24小时60个新键、最多8个非终态映射；手动采集为6/48/8。不同绑定/订单共享额度，合并也计额。数据库owner锁内先重放原键、校验摘要，再检查预算，拒绝事务不留operation/run/映射/Outbox。余额浏览器执行冷却保持30秒。

Payment签名调用方通过`/internal/v1/controls/payment-balance-refresh`提交binding_id/order_id，Room生成原订单固定键，使用独立6/60/8额度。Gateway不能调用该用途，公开DTO拒绝额外来源字段；不增加Secret或服务权限。旧支付固定键保持重放。前端429保存原键和重试截止时间，按钮等待Retry-After，重载后也不自动换键重试。

手动采集新映射保留180天；旧映射的有效保留边界取`MAX(expires_at, created_at+180天)`，后续归档不得按原七天删除。二维码旧映射创建时间安全默认迁移时刻；Room沿用原创建时间。已超新配额的旧数据保留，新键暂停、旧键可恢复。

## 快照回收

每事务最多1000成员、4个父快照，每个owner最多选1个快照，以owner游标轮转。分页共享锁由`FOR UPDATE SKIP LOCKED`跳过，先子后父，原始样本保留；配额仍按父行total计，父行完成回收才释放。

每轮最多10批、开始下一批前检查500毫秒软预算，提交归还连接后让出事件循环。有积压1秒、空闲60秒，业务占用达到基础池大小时15秒再试；原恢复扫描15秒独立计时。SQL本身不承诺500毫秒内完成。停止信号不再开新批，后台关闭不运行清理。

日志只有分类/数量/耗时，逐批记录删除成员/父行、跳过锁数量、候选父行保守成员量、所见最老到期年龄和压力暂停次数；统计最多扫描64个候选，不把候选统计称全库准确积压。
