# 开发与阶段验证

更新日期：2026-10-01。工程版本：0.7.0。

frontend/backend 的依赖和构建输入独立于 example。example 只用于参考截图；学校数据、订单与验证码均不由占位页面生成。

## 工程环境

- 后端：Python 3.12.10、uv，`backend/uv.lock` 锁定依赖。开发机执行 `cd backend && uv sync --locked`。
- 前端：Node.js 22.23.2、npm 10.9.8；开发机执行 `cd frontend && npm ci`。
- 锁文件使用 `node:22.23.2-bookworm-slim@sha256:48e4b67d85f87bd551df43704e24d252f56cc5f8e9718841aace50f19948f0f9` 容器生成。可在仓库根执行：

```sh
docker run --rm -v "$PWD/frontend:/app" -w /app node:22.23.2-bookworm-slim@sha256:48e4b67d85f87bd551df43704e24d252f56cc5f8e9718841aace50f19948f0f9 npm ci
```

安装完成后，正式前端在 frontend 执行 `npm run dev`，构建、规则检查分别执行 `npm run build`、`npm run lint`、`npm run typecheck`。

## 契约与离线验证

在 backend 执行：

```sh
uv run ruff check .
uv run pytest -q
uv run python -m scripts.generate_openapi --check
uv run python -m scripts.generate_protocols --check
uv run python -m scripts.schema_catalog --check
uv run python -m scripts.migrations --domain all --sql --output-dir /tmp/elect-ddl
```

修改 DTO/端点、内部 DTO/状态或初始表声明后，分别运行上述生成器（去掉 --check），再在 frontend 执行 `npm run contract:generate`。OpenAPI 类型已提交，普通前端生产构建只读取 frontend；契约检查/生成属于开发流程，读取 docs/contracts。

前端验证执行 `npm run contract:check && npm run lint && npm run typecheck && npm test && npm run build`。Vitest 验证 MSW 的学校失败、未知订单和部分历史分支；后端按 OpenAPI 校验全部场景。T1 已建立路由/会话/公共操作的组件和 Playwright 验证，`npm run test:e2e` 启动 Vite 并使用合成响应；真实业务 E2E 在 F2 以后增量建立。

## MySQL 实际迁移验证

T0 已在独立临时 MySQL 8.4.8 容器通过在线建表/重复升级与账号/约束检查。测试仅在显式 `ELECT_TEST_MYSQL_DISPOSABLE=1` 且配置 `ELECT_TEST_MYSQL_ROOT_URL_FILE` 时运行；该文件包含临时 root 的 mysql+asyncmy URL，位于仓库外、权限 600。测试创建七域库及独立 app/ddl 账号并替换临时同名账号，须使用专用一次性实例。

```sh
cd backend
ELECT_TEST_MYSQL_DISPOSABLE=1 ELECT_TEST_MYSQL_ROOT_URL_FILE=/absolute/temporary/root_url uv run pytest tests/integration/test_mysql_migrations.py -q
```

每域 `uv run python -m scripts.migrations --domain identity` 的在线连接读取 `ELECT_IDENTITY_DDL_URL_FILE`，其他域类推（学校域使用 SCHOOL_ADAPTER）；URL 数据库必须匹配领域。正式统一持锁迁移执行器为 `python -m services.migrate_all_mysql`；离线 provisioning 为 `python -m services.deployment.provision`，使用方法见部署说明。

## 本地真实测试凭据

用户在仓库根提供 `auth.txt`，供当前及后续学校真实测试使用。该文件已加入 `.gitignore`，正式镜像构建只读取 frontend/backend，两端 `.dockerignore` 也排除同名文件。它不是公开配置模板或生产 Secret，不提交、不复制到 docs/夹具、不打印正文；仅在测试进程内读取，日志和验收记录使用应用 ID 或输入类别。

学校认证、当前用户及本人绑定等只读检查可使用此文件；真实绑定写入、支付建单/付款和邮件验收需要已明确选定的目标、金额与邮箱。读取凭据不等同于授权执行全部外部副作用。

本轮烟测通过学校文档参考代码在内存执行 A01–A04/B01/B02，使用临时工具依赖，不纳入正式应用锁；最多两次验证码 OCR、一次认证提交，不执行建单/绑定/支付表单。

```sh
cd backend
uv run --with ddddocr --with requests python -m scripts.school_readonly_smoke --record ../docs/acceptance/school/readonly.json
```

命令只输出分类结果与绑定数量。它读取 docs 中的开发参考，不是生产 Adapter，也不能用于证明正式应用会话或加密激活已完成。历史结果见 [2026-10-01 记录](acceptance/school/2026-10-01-readonly.json)。

## T1 Docker 验证

仓库根 `sh deploy/check.sh` 执行全部离线规则/契约/构建/浏览器验证；`sh deploy/test-stack.sh /absolute/new-directory elect-test-name` 生成独立环境、启动空库并运行实际 Outbox/Inbox/审计/权限检查。两者只需 Docker Engine/Compose，测试镜像可挂载 docs/合成夹具，生产镜像仍独立。详见 [部署说明](Docker部署配置说明.md)、[前端验收](acceptance/frontend/T1公共层验收.md)。

## T2 验证入口

全新 deploy/test-stack.sh 除 T1 基础烟测外，执行 python -m scripts.t2_smoke：真实 MySQL/Redis、合成学校、无外部业务写入。真实联调显式执行 python -m scripts.t2_school_readonly --auth-file /run/test-auth --origin https://elect.test.local --ca-file /run/test-ca；后台恢复执行 python -m scripts.t2_school_recovery --auth-file /run/test-auth。均只在内存载入凭据、输出分类/数量，使用独立验收容器只读挂载 auth.txt，不进入 CI/普通启动。证据位于 docs/acceptance/school/2026-10-01-T2-*.json。

以 root 读取属主不同的只读 Secret 时，临时烟测容器需要 DAC_OVERRIDE；生产服务保持 UID 10001/cap_drop ALL。普通页面使用人工验证码，烟测 OCR 仅用于指定账号验证。

真实生产前端的显式浏览器入口：在 frontend 执行 ELECT_BROWSER_PATH=/usr/bin/chromium node scripts/t2-live-browser.mjs --auth-file /absolute/auth.txt。使用 elect.test.local 验收域名与本机 18443 映射，OCR 仅用于指定账号烟测，密码/验证码/token 不进入输出、trace 或截图；脚本依赖开发机 backend/.venv，不替代仅 Docker 的部署/CI 入口。

## T3 筛选绑定与真实指定验收

新版公开增加三级 FilterChoices 列表和本人 Binding 读取，OpenAPI 当前 33 个方法/路径。升级 Secret 后执行 room_0003/school_0004，既有 Room Worker 自动扫描同步/默认/绑定，详见 [绑定决策](decisions/T3绑定筛选与异步界面.md)。完整 test-stack 增加 t3_default_smoke 和 t3_binding_smoke，合成期间暂停真实 Worker，结束后确认任务终结才恢复。

指定真实新增由生产前端显式执行，须先完成合成/容器验收，并在独立项目仅临时打开绑定开关：

```sh
cd frontend
ELECT_BROWSER_PATH=/usr/bin/chromium node scripts/t3-live-binding.mjs \
  --auth-file /absolute/auth.txt --target 枫苑5号-402 \
  --record ../docs/acceptance/school/2026-10-01-T3-binding.json
```

脚本核验唯一楼栋/楼层/房间与精确候选，仅提交一次逻辑绑定，202 后查原操作，unknown/失败不再次写入；已存在时不新增。验收域名为 elect.test.local、本机映射 18443，OCR 只用于本次指定账号。不截图/trace，不输出账号、密码、Cookie/token 或学校原始记录。台账分类证明使用 `scripts.t3_live_binding_proof --operation-id <应用操作ID>`，只读取对应独立验收环境的领域凭据，不访问学校。验收后恢复 false 开关，不因此开放其他目标、SMTP 或付款。

## T3 真实指定删除

先完成 t3_removal_smoke/完整容器验收与版本升级，在独立项目临时打开学校写开关：

```sh
cd frontend
ELECT_BROWSER_PATH=/usr/bin/chromium node scripts/t3-live-removal.mjs \
  --auth-file /absolute/auth.txt --target 枫苑5号-402 \
  --record ../docs/acceptance/school/2026-10-01-T3-removal.json
```

该脚本只选择本人列表唯一匹配的明确目标，提交一次 DELETE，正常等待两次至少30秒的成功缺席与服务端终态；unknown 不重发。用 scripts.t3_live_removal_proof --operation-id <应用操作ID> 读取台账分类证明，随后恢复 false。三份真实脚本共享认证和浏览器同源读取，凭据只在内存，不截图/trace/输出学校 IDs。
