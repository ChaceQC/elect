# 七容器核心组合验收

日期：2026-10-05（Asia/Shanghai）；版本：0.19.0。方案见[实施决策](../decisions/七容器核心组合.md)。

## 实现与实际运行

- 一个core Web进程保留Gateway及Identity、Room、Monitoring、Payment、Notification控制、Audit的独立上下文。原52个内部接口直接复用身份依赖、输入/返回DTO和领域服务；Adapter/邮件仍认证HTTP/TLS，复用原签名与内部证书。
- 七域数据库结构不变，8个应用池仍2+1；持久事件、独立心跳、MQ推送和有限退出预算保留。核心先初始化全部上下文再开后台，退出先同时停止领取，再关闭各域资源。部分启动失败与后台失败健康检查已验证。
- 邮件入口不创建FastAPI应用；正常常驻导入不加载Alembic，镜像构建生成迁移head清单，CI校验源码清单。
- 实际独立项目elect-test-core-local启动core、school-adapter、mail-worker、mysql、rabbitmq、redis、nginx共7个健康容器；公开协议经Nginx→core返回200。核心TLS及各领域后台角色检查通过。
- 停RabbitMQ后core继续服务且显示degraded，重启后恢复ready；restore组合全部领域后台为空，独立后台入口拒绝启动。合成同步/默认Saga/采集、支付D01响应丢失仅发一次、DATA后邮件unknown恢复通过。
- 使用原Secret和原卷回退combined，13个容器全部健康，旧core和mail-worker已停止，未重建Secret或卷。完整CI结果在PROJECT_PROGRESS.md记录。

## OCR与合成工作负载

- 独立无网络OCR进程，合成1+2图片推理10次；加载0.5328秒，推理P50 9.526ms、最大13.059ms，峰值RSS 118632KiB，2秒空闲CPU 0.0001秒，进/出算子线程均1。不是完整Adapter加载OCR后的容器峰值，不证明学校验证码准确率。
- 50个合成账号/监控集中到期，运行真实领域后台与原2个监控槽，核心间直接调用，数据库/MQ/Redis为实际容器，学校由合成transport处理。同时5并发执行150次公开页面读取。50个run全部succeeded且恰好50个样本；工作阶段5.855秒，验证进程峰值RSS 114484KiB。没有替换生产Worker或手工写succeeded；测试结束关闭合成监控。
- 这些峰值属于独立测试进程，不能与7容器空闲数直接相加声称完整部署峰值。真实学校监控、完整Adapter OCR高峰、真实支付/SMTP负载、目标机2核2GB/50人24小时与冷机独占部署仍需分别验收；本轮没有读取真实学校/邮件凭据或发送真实副作用。

## CI修复范围

原dev的pytest同名收集冲突、旧认证组件仍点击已删除按钮、旧T2手工夹具缺少默认副作用策略，以及组合健康清单漏掉Room control/Payment reconciliation均已修复。Nginx为读取原应用UID的0400 CA增加DAC_READ_SEARCH，不修改现有密钥权限。新增核心切换/恢复/50监控门禁，CI作业上限调整至45分钟以覆盖新增有界步骤。

新增回退检查结束后会恢复13个后台容器，旧独立100计划容量驱动需先按测试项目标签停止全部应用/profile，避免生产Worker与夹具争抢任务；CI已增加这一隔离步骤，保持原领取/租约语义。

修复后本地定向验证：100个计划/8并发、100个签名唤醒与Inbox以及每run唯一样本通过；真实静态前端/Nginx/领域容器在1440/375px读取8页面，跨来源、CSRF、越权拒绝、跨标签退出与会话吊销通过，模拟路由0、页面错误0。验证后所有测试容器/网络再次清理，原elect-wsl继续健康运行。
