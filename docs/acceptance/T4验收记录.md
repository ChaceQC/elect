# T4 查询与持久采集验收

日期：2026-10-01；版本：0.8.0；结论：T4-01..04、P4/P5b、F4/F5-05完成。M2仍等待T5低余额邮件闭环。

## 交付行为

- B02余额按本人Binding与学校roomId精确对应，账号合并只合并请求。目标缺席/未知值不会使用其他房间余额，保留该房间最后成功值和时间；手动刷新不生成监控样本。
- C02按7天窗口持久推进，同账号单飞、有限重试、租约恢复。成功范围以内容快照替换，保留同日多条/内容重复行；失败保留旧记录，空响应不补零。
- 上海含首尾日期、最多366天；日/周/月桶只聚合选定范围，金额用Decimal。当前没有全日完整覆盖证据，已知合计标partial，完整昨日消费保持null。
- 独立5秒Scheduler/Worker/15秒恢复器、45秒租约/10秒续租/90秒attempt、三次重试、持久Outbox/Inbox。逻辑槽和有效运行合并，完成槽不复活；失效代次/凭据/目标/epoch/租约拒绝提交。
- 首批成功样本为balance_only；唯一run样本、失败不移动基线、切换默认重置基线、取消本次保留后续计划。快照固定实际ID集合，30分钟TTL、410过期/400范围不符，关闭后历史仍可读。
- 正式总览、逐房间余额、7/30/90/自定义范围、消费图表、固定分页、立即采集/取消与刷新恢复接通。范围、粒度和页码保存在路由query；刷新第二页先建立新快照再读取该页。未知点保留断点，零值保留，金额展示使用原十进制字符串。
- monitoring_0004保存采集时的间隔；内部指标展示调度/到期任务/租约/尝试和Outbox积压。Compose共25个长期进程，学校写/支付/SMTP默认false。
