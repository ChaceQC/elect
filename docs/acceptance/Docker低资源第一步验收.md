# Docker低资源优化第一步验收

日期：2026-10-03（Asia/Shanghai）；版本：0.14.0。对应[实施决策](../decisions/Docker低资源后台生命周期.md)及[优化方案](../Docker低资源部署优化方案.md)第一步。

## 本批交付

- 公共角色接口、同域上下文共享、任务监督、独立心跳、信号停止领取和在途退出。
- Monitoring API/Relay/Scheduler/Worker/恢复/提醒回报合并为一个Python进程，保留原独立入口和角色租约/幂等/取消语义。
- 试点覆盖默认禁用五个旧角色，恢复覆盖与入口级开关共同禁止后台。基础组合为25个长期容器，尚未形成最终13容器组合。
- 新增单位和真实MySQL/Redis/MQ合成验证入口，不使用真实学校或邮件凭据。

## 验证

- `sh deploy/check.sh`通过：后端ruff、176 passed / 1 skipped、公开/内部契约、数据库目录与七域离线迁移；前端规则/类型/契约、49项单元组件、32项浏览器及构建通过。
- 新增10项生命周期单位用例，覆盖独立心跳/重启清零、同域上下文和连接共享、重复启动拒绝、意外退出/异常/停滞可见、停止领取后在途完成或超时取消、统一信号和后台禁用。最终重复启动保护后后端176项重新通过。
- 公开Compose解析确认基础30个长期服务；Monitoring试点为25个，五个旧角色均在非默认profile；restore最后应用时全部八个API强制后台禁用。配置解析不作为容量证据。
- 隔离test-stack的空库初始化/七域权限、可靠事件、T2/T3/T4/T5/T6各阶段复验通过；包括真实MySQL/Redis/MQ中断、重复消息、取消/默认/凭据屏障、模拟SMTP DATA未知和支付一次发送。最后重建独立模式，30个长期服务全部healthy，旧卷升级与内部TLS预检正常。
- `sh deploy/test-monitoring-combined.sh`最终通过：真实容器内API和五角色健康；已建立的共享MQ连接断线后API显示degraded，四个业务角色继续推进数据库扫描；真正应用恢复组合后API可启动、后台角色为空、独立入口拒绝。
- 同一隔离脚本的合成学校进程验证调度成功/单run单样本、等待学校期间控制/健康查询可用、运行中取消零样本、单角色退出健康失败、恢复器接管、重启拒绝旧epoch、停止领取后等待在途提交及AMQP资源关闭。测试主动推进一次租约期限，不作为真实等待时间或容量测量。
- 后端生产/测试镜像实际构建通过；最终源码与公开配置检查、受影响文档链接、版本锁文件及真实凭据忽略检查通过。CI新增合并角色阶段，合成验证不访问真实学校/SMTP/支付。
- `sh deploy/test-t7-recovery.sh`通过：实际MySQL加密快照和封存binlog、隔离恢复、62张表计数保留、密文可读、快照后模拟建单/邮件保持unknown、旧Outbox不自动重放；本次本机合成演练RPO 4.577秒、RTO 65秒，不代表生产异机或持续灾备。

## 验证中修正

- 首次隔离启动因宿主机历史Docker网络耗尽默认地址池失败。仅为本次测试项目显式创建未占用的小网段后继续空库启动，未清理历史网络、改Docker全局配置或启动原业务项目。CI使用独立Runner的默认地址池。
- T4旧夹具假设默认为合成001，但0.13.1规则按学校顺序选择了002。已通过正式默认切换接口显式选001并等待终态，保留原余额差、切换与去重断言；修正后T4复验通过，生产默认规则不变。
