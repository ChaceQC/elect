# Docker低资源第四步验收

日期：2026-10-04（Asia/Shanghai）；版本：0.17.0。

对应[优化方案](../Docker低资源部署优化方案.md)第四步和[执行效率决策](../decisions/Docker低资源执行效率.md)。仅使用本轮隔离MySQL/Redis/RabbitMQ及合成学校/SMTP/支付；没有读取auth.txt/email_auth.txt或启动原业务部署。

## 交付

- 本域DomainEngine在完整COMMIT成功后提示Outbox，回滚/取消/提交失败不发提示，连接局部标记在池归还前清除。跨进程提示缺失继续靠数据库扫描。
- Relay/Audit空闲1→2→5→10秒退避，积压每批最多16条；失败重连有界且加抖动。保留发布租约、签名、confirm后条件标记及持久重试。
- 六类消息消费改为basic.consume和有界prefetch=1/本地缓冲，重连使旧缓冲失效、未ACK由MQ重投。签名、Inbox事务和提交后ACK由原领域保持。
- Monitoring两个TaskGroup执行槽共用本域池/客户端/AMQP连接，各有独立channel；邮件发送独立单槽，DATA前许可/有限重试/unknown不变。保留学校全局5/后台4/账号1限制、原90秒采集预算和统一退出预算。
- 各类执行与回报按空闲退避，Scheduler/恢复/控制周期分别保留；Adapter清理改为每60秒、每批100行，积压继续小批，空闲每10秒实际读库更新健康。
- 修复已登记room.binding_confirmed缺失MQ发布权限：补最小权限及既有Monitoring运行队列路由，签名提示只写Inbox、不依据提示创建run。已有Secret离线重复upgrade_controls并重建MQ；密码/密钥与原卷保留，无新迁移。

## 发现与修正

- 第一小步Actions及顺序本地复测在ready检查失败；实际MQ日志确认既有room.binding_confirmed发布被拒绝。补权限、路由和签名Inbox消费后，旧Secret升级及七域ready/双向切换通过，没有放宽健康判定。
- 首次同一隔离栈两轮误重叠；最终所有会改动该栈的检查按顺序执行，分别通过。双槽下旧“瞬时空闲连接数”断言也不再适用，改为真实借满池容量及并发API/续租验证。
- 资源复测继承umask077，公开测试ACL变为600导致独立Redis无法启动；测试脚本显式设公开ACL644，受限目录及正式Secret规则不变，新证据目录复测通过。没有删除失败证据或调整生产ACL。
- 默认Docker地址池耗尽，仅为本轮来源/恢复项目使用10.247/10.248内部小网段，不清理历史网络或改全局地址池。
