## 4. 隔离入口与生产连接预算

已静态核对[一次性脚本](../../../deploy/test-query-resources.sh)和[查询资源辅助](../../../backend/tests/integration/query_resource_support.py)：

- 脚本建立唯一elect-test-query前缀的internal网络及一次性MySQL8.4.6，无主机发布端口；MySQL数据在tmpfs，512MiB容器限制、384MiB数据tmpfs。
- 仅只读挂载backend/services、tests、scripts，不挂Secret或业务卷；连接使用内部query-mysql，合成空库名为随机elect_query_test前缀。退出trap只清理本次容器与网络，辅助finally删除本次新建库。
- 当前只运行test_snapshot_admission.py和test_history_admission.py；没有R1新增回归用例，不能把当前入口成功描述为AUD-10/11已解决。
- 默认检查镜像为elect-backend-check，可用ELECT_QUERY_TEST_IMAGE指定。R1执行前须按当时源码和锁文件构建test阶段镜像并记录镜像ID/来源SHA，不能只靠旧镜像可启动。CI在本次checkout构建检查镜像后运行该脚本。
- WSL中已有mysql:8.4.6与elect-core-check:latest等缓存，但无默认elect-backend-check标签；这些旧缓存未验证对应当前SHA，R0未将其作为受测镜像，也未进行额外构建。
- 本地脚本工作树是CRLF，Git索引为LF；后续Linux验证使用同SHA的独立LF检出，不能直接运行Windows CRLF脚本或使用旧elect-wsl检出代替当前源码。本轮未转换文件或建立检出。
- 合成入口只使用ELECT_TEST_QUERY_MYSQL_HOST=query-mysql；不设置指向业务库的ELECT_TEST_MYSQL_ROOT_URL_FILE。现有文件入口同时依赖ELECT_TEST_MYSQL_DISPOSABLE=1，但标志本身不证明目标是一次性库，不能将业务URL交给它。

连接预算差异必须单独记录：

## 5. 数据处理和证据保存

1. 存量命令默认dry-run，限定领域/范围/状态，只输出候选、可修、跳过和冲突计数。apply显式指定目标，按有界小批事务重新检查归属/状态，支持断点、幂等重跑和停止。
2. apply与DDL分开，不能藏在启动或迁移中。先在合成旧数据演练，再按目标环境授权审查摘要、备份和维护窗口；不读取现有业务数据来完成R0。
3. unknown、dispatched、邮件DATA/发送标记及防重放证据保持；不统一改成功、不盲重放。历史修复只处理可证明主从关系，孤儿/循环/冲突留待诊断，不为回滚把正确终态改回running。

5. 维护权限不下放给普通业务服务；镜像回退不能恢复已删除数据，恢复也不能激活旧Outbox、会话或未知支付/邮件任务。
