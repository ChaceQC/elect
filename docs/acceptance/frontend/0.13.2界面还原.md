# 0.13.2 前端界面还原

日期：2026-10-03（Asia/Shanghai）。本次按用户要求重写正式前端的展示层，并按追加要求精简常驻文案。

## 视觉基准与实现

基准为 `example/nature.html`：`StudentApp` compact 模式、`student.css` + `blue.css`。既有截图位于 [reference](reference/manifest.json)，正式页面仍只使用 `frontend/` 的独立源码、依赖和构建上下文。

| 界面 | 实现 |
| --- | --- |
| 公共布局 | 238px 白色桌面侧栏、77px 顶部栏、39px 内容边距、四个相同导航和图标；手机恢复顶部横向导航，账户入口可达 |
| 登录 | 双列浅蓝故事区与登录表单；同源学校验证码、使用协议和自主后台授权 |
| 总览 | 余额/用户信息双列、三张统计卡、浅蓝消费趋势；成功空绑定进入参考式首次引导 |
| 明细 | 横向余额卡、时间范围、双日期字段和内联日历、月/周/天分段切换、采集表 |
| 绑定 | 一张列表卡、搜索、新增绑定弹窗；保留学校三级筛选、确认、默认切换、删除与未知操作恢复 |
| 监控 | 寝室条、邮箱/阈值与监控参数两列、开关和保存；关闭监控独立可用，运行详情折叠 |
| 弹窗 | 同一圆角、间距、按钮和遮罩；支付、协议、账户与确认均保留键盘焦点管理 |

文案不复制被浅蓝主题隐藏的口号、页面介绍、装饰说明；删除“当前快照固定记录集合”“应用充值规则”等界面技术文本。候选选择不重复解释步骤，完整历史不常驻覆盖度说明。异常、部分数据、过期/未知余额和提交结果仅在对应状态出现。运行详情默认折叠；设置冲突时自动展开已保存值供核对。采集异常、邮件失败/未知和取消待确认仍直接显示。

## 保留的业务差异

- 示例余额、日期、算术验证码和演示标签不进入生产。截图通过测试拦截响应，使用合成账号/寝室、86.42 元等对比数据；不表示学校实时数据。
- 登录插图沿用源代码中的 Home/Zap 图标和布局，装饰余额替换为 `ELECT`。学校验证码由 API 返回，授权不预勾选。
- 只有多个寝室或独立查看时显示切换控件；已有真实功能如同步、刷新、删除、缴费和关闭监控仍可操作。
- 消费图表没有默认数据；null 保留断点。表格保留学校读数来源与质量，不能复制参考按余额虚构的用电读数。
- 日历使用校准后的上海日期，上限366天；手工修改、快捷范围和日历选择只修改草稿，应用后才更新URL/请求。提供跨月方向键、未来日期禁用和Esc焦点返回。
- API 字段、幂等键、202处理、版本/草稿、快照分页、订单恢复与未知状态规则未改动。版本升至0.13.2，后端只同步版本元数据。

## 验证入口

在 `frontend/`：

```sh
npm run lint
npm run typecheck
npm run contract:check
npm test
ELECT_UI_SCREENSHOT_DIR="$PWD/../docs/acceptance/frontend/ui-rewrite" \
  npm run test:e2e -- --workers=2
npm run build
```

如使用系统Chromium，可显式设置 `ELECT_BROWSER_PATH=/usr/bin/chromium`。视觉用例覆盖1440/375px，原有集中回归覆盖375/390/768/1280/1440px、账户、长错误、草稿、绑定未知、支付恢复、固定分页及图表释放。

## 验证结果

- `sh deploy/check.sh` 通过：后端 ruff、166 passed / 1 skipped、公开/内部协议/表目录检查、七域离线迁移；前端规则、类型、契约、49项单元组件、生产构建和32项浏览器回归通过。跳过项为需要临时 MySQL 的集成检查。
- 最后调整手机明细余额卡、监控提示字号及日历字重后，重新构建前端 test/browser-test 镜像，在无网络容器完整复验：49项单元组件、32项浏览器和规则/类型/契约/构建全部通过。最终 `elect-frontend:v0.13.2` 生产镜像构建成功。
- 本机 Chromium 对最终生产 build/preview 完成3项视觉场景，保存1440×1000、375×1000视口的16张页面/弹窗全页截图；同尺寸并排对照和局部放大检查通过，详见 [视觉QA报告](design-qa.md)。
- 手机明细页缴费按钮保持在余额右侧；日期跨月键盘、未来日期/366天约束、Esc焦点恢复、首次空绑定引导、失败态、设置冲突核对、支付未知订单恢复、双标签会话与图表释放通过。
- 两轮发现的旧支付文案断言和空绑定夹具缺少响应元数据已修复后复验。检查无页面脚本错误或视觉场景意外API请求；未用删除业务断言的方法规避失败。
